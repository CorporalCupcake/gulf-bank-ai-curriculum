    Learning Without Labels, and Generating the Data That Isn't There

    How a model learns what "normal" looks like from unlabelled data, why contrastive learning works, and what VAEs, GANs and diffusion models offer a bank.

    Contents

    The whole lesson in one sentenceLabels are scarce but data is abundant, so you invent a task whose answer is hidden in the data and keep the representation it learns; generative models learn the whole distribution so you can sample from it, which helps with synthetic data and risks privacy.

    Part 1

    The intuition

    A Gulf bank holds billions of card transactions but only a few thousand confirmed fraud cases. Data is cheap; labels are not.

    Self-supervised learning hides part of the data and asks the model to restore it. To predict a hidden transaction amount, the model must learn what normal spending looks like. That knowledge is the representation, and it is what you keep. A handful of labels then attaches the real task (this is fraud).

    Hold onto thisSelf-supervision moves the cost from labelling to designing the pretext task and checking the representation.
    Part 2

    How it really works

    Pretext tasks: predict the hidden part

    Nearly every pretext task is one of three families: predict the next item (GPT), fill in a masked part (BERT), or tell views apart (SimCLR, CLIP).

    You pretrain once on all the unlabelled data, then adapt: freeze the representation and train a small model on top (a linear probe), or fine-tune gently. When anyone claims a win, ask for accuracy against number of labels, with and without pretraining (M1.2).

    Contrastive learning: spot the twin

    Take an anchor, a positive (another view of the same thing) and many negatives. Train the encoder to put anchor and positive close and negatives far. A falling loss alone does not prove good features. A low temperature makes the loss focus on the hardest negatives: sharper, but more fragile. The augmentation decides what the model keeps: whatever the transformations leave unchanged.

    The loss assumes everything except the positive is a true negative. In banking that is often false: two accounts of one customer are pushed apart anyway. This is the false-negative problem. Keep known relatives out of each other's negatives.

    Without negatives: collapse

    Without negatives there is a cheat: output the same vector for every input, and every positive pair is perfectly close. This is collapse. Methods avoid it with negatives, a teacher copy (BYOL, DINO), variance penalties, or reconstruction. The loss can look fine while every customer looks alike, so track a linear-probe score during training.

    What it looks like on bank data

    Treat a customer's history as a sentence of tokens, pretrain with masking, then fine-tune for fraud or churn. It beats a tuned gradient-boosted model mainly when labels are scarce (foundation models for transaction data). Contrastive embedders power policy search and complaint triage (trade-finance document AI), though English-heavy encoders underperform on Arabic (Arabic LLMs).

    Two cautions. Pretraining can leak the test period (F3.1). And the representation inherits its population, so check by segment (G2) and protect embeddings like the source data (G2.4).

    Generative models: the map

    A generative model learns the data well enough to draw new samples. Each family bets differently: VAEs compress and decode, GANs pit a forger against an inspector, diffusion denoises, and autoregressive models (language models) predict one piece at a time.

    VAEs: compress, regularise, decode

    An ordinary autoencoder squeezes an input into a small code and rebuilds it (F4.4), but a random code decodes to garbage. A variational autoencoder keeps all codes in one smooth region, so any random code is valid. Samples come out blurry, but poor reconstruction flags an unusual input, so VAEs suit anomaly detection (F4.4).

    GANs: the forger and the inspector

    A generator turns noise into samples while a discriminator tries to tell real from fake, and each forces the other to improve. Training is touchy: the generator may produce only a few outputs that fool the inspector (mode collapse). For a bank, GANs matter mainly as the engine behind deepfakes that attack eKYC (A3.5).

    Diffusion: remove noise, run it backwards

    Add noise to data until only static remains, then train one network to undo one small step at each noise level. Start from pure noise, apply it repeatedly, and a plausible sample emerges. Modern image generators work this way, with transformer denoisers (F5.3; diffusion language models).

    Using generated data in a bank

    The direct use is synthetic data: records that look like customers but are none, for test environments, sharing, or augmenting a rare class (F3.5). Judge it on three axes and demand all three. Fidelity: does it look real? Utility: does a model trained on it work on real data? Privacy: does it leak real rows?

    The axes conflict: a copy of the training rows has perfect fidelity and no privacy. Outliers are memorised most easily (R11). "Synthetic" is not a legal synonym for "anonymous": take it to privacy and legal teams.

    Part 3

    How it fails, and how to spot it

    • Pretraining that sees the test period

      Embeddings pretrained on all history, then "tested" on a month they have seen.

      Spot itPretraining must end before evaluation starts.
    • Collapse that the loss hides

      The loss falls while every customer maps to nearly the same vector.

      Spot itRun a probe at every checkpoint.
    • "Pretrained, therefore good"

      Success on the full labelled set says nothing about pretraining's benefit.

      Spot itAsk for the label-efficiency curve against a tuned gradient-boosted baseline.
    • Generators judged by eye, or memorising

      Ten synthetic records look fine, but tails are missing or rows are near copies of real ones.

      Spot itCompare rare segments, run train-on-synthetic test-on-real, and check nearest-real-row distances.
    Part 4

    Self-check

    Try each before opening the answer.

    1. Why does restoring a masked transaction history help fraud detection when the model never saw a fraud label?

    It learns normal behaviour: habits, timing, typical amounts. Fraud is a departure from that, so labels only teach which departures matter.

    2. You lower the temperature. How does the loss treat easy and hard negatives?

    Hard negatives take a larger share of the push and easy ones are ignored. The embedding gets finer but more sensitive to false negatives.

    3. What is collapse, and name two ways methods prevent it.

    The same embedding for every input, which makes any positive-pair loss zero. Negatives, a teacher-student setup, variance penalties or reconstruction targets prevent it.

    4. A synthetic table passes distribution tests and a model trained on it scores AUC 0.91 on real data against 0.92 for real training. Safe to release?

    Not yet. Fidelity and utility are shown; privacy is not. Check nearest-real-record distances and membership inference, then get legal approval.
