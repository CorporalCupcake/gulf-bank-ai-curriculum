    Pretraining and Post-Training: From Text Predictor to Assistant

    Part 1

    What the two stages are

    In one sentencePretraining teaches a model to predict the next word by reading a huge amount of text; post-training then teaches it to behave like a helpful assistant.

    Our running example is one question: "What is the capital of the UAE?"

    Picture a new hire who has read most of the internet but never held a job. Asked that question, they might carry on as a quiz page would, with another quiz question. They know the answer. Nobody has told them that a question means "give an answer".

    How it differs from other things you know

    • Training a classifier needs labelled examples (this email is spam). Pretraining needs no labels: the next word of the text is the answer key.
    • Search looks documents up. Even a finished assistant looks nothing up. It produces probabilities for the next token and one is picked.
    • Pretraining vs post-training: pretraining supplies what the model knows. Post-training supplies how it behaves.
    Part 2

    How the stages work

    1. Pretraining. Show the model passages of text, a piece (token) at a time, and ask it to guess the next token. A confident wrong guess is punished hard; a confident right one costs almost nothing. Repeat over trillions of tokens of web pages, books, code and papers.
    2. Supervised fine-tuning (SFT). Show it thousands of worked examples: a user request plus an ideal reply. It learns the format of helping. Pretraining holds the knowledge; SFT mostly teaches style.
    3. Preference tuning. Show it two replies to the same question with one marked better. It learns what people prefer: direct, polite, honest about doubt, willing to refuse what it should. The common methods are RLHF (reinforcement learning from human feedback) and DPO (direct preference optimisation, a simpler version).
    4. Reinforcement learning on checkable answers. For maths, code and similar tasks, the answer can be checked automatically, so correct answers are rewarded. This is how reasoning models are built; DeepSeek-R1 (January 2025) showed long step-by-step reasoning emerging this way.
    5. Sampling at run time. At each step the model gives a probability for every possible next token, and something must pick one. That is sampling, and you control it.

    Why does next-token guessing produce knowledge? To continue "The capital of the UAE is", the model has to have absorbed the fact. Translation and summarising emerge because they help prediction.

    The result of pretraining is a base model: a strong text-continuer with a knowledge cut-off (it has read nothing after a certain date). It will happily continue toxic, wrong or irrelevant text.

    How to think about it

    • Size. Frontier models read around 15 trillion tokens or more, using millions of GPU-hours. Few organisations do this; a bank will start from an existing model. SFT, by contrast, uses thousands to millions of examples.
    • Facts come from pretraining. Fine-tuning on facts the model did not know tends to teach it to sound confident about things it cannot back up (Gekhman et al., 2024). For policies or this week's rates, give documents at query time instead.
    • Style comes from post-training. LIMA (Zhou et al., 2023) got strong chat behaviour from about a thousand examples.
    • Every stage costs something. Preference tuning can make a model flattering (people rate flattery highly), wordier and less varied in its answers.

    Sampling settings

    • Temperature is a volume knob on the gaps between scores. Below 1 the favourite gains; above 1 the choice flattens; at 0 the top token always wins (greedy). It never changes which token ranks first.
    • Top-p keeps the smallest set of tokens whose probabilities add up to p (say 0.9) and drops the long tail. The set grows when the model is unsure and shrinks when it is sure.
    • Top-k keeps the k likeliest tokens. Simpler, but the right k varies from step to step.

    Truncation matters because thousands of unlikely tokens add up. A 1-in-1,000 bad token per step is a near-certain derailment over 500 tokens. A common choice is mild temperature plus top-p of 0.9 to 0.95.

    Why the same prompt gives different answers

    • Sampling randomness. At temperature above 0 every token is a draw. A short label may match across runs; a 300-word answer almost never will.
    • Prompt sensitivity. An extra space or a different retrieved passage changes the output.
    • Numerical effects, even at temperature 0. Servers split work differently with load, and floating-point sums depend on order. When two tokens are nearly tied, the winner can flip.

    So say "low-variance", not "deterministic". Compare decisions, not exact wording.

    Which stage to change

    RL on checkable answersProblems with verifiable answersMulti-step reasoningUneven where answers can't be checked

    Sensible settings by task:

    • Classification, extraction: temperature 0 or very low.
    • Summaries and answers from documents: low (0 to 0.3). High temperature invites invented detail.
    • Drafting and brainstorming: 0.5 to 1 or more, with top-p around 0.9 to 0.95.

    In banking, use retrieval, not fine-tuning, to teach a model your policies, and test each case several times because one run proves little.

    Part 4

    Common mistakes and quick check

    • Fine-tuning to teach facts

      The model answers fluently but sometimes wrongly, with no source. Use retrieval for content; keep fine-tuning for format and tone.

    • "Temperature 0 means deterministic"

      Output still varies through numerical effects and model updates. Pin the model version and re-test on any change.

    • Using a base model as an assistant

      It rambles. Check the model name for "instruct" or "chat".

    • Testing one run

      "9 of 10 right" from a single pass may be 7 on the next. Run several times and report the range.

    1. What does lowering the temperature do to the probabilities?

    The favourite takes a bigger share and the tail shrinks. The ranking never changes, so temperature adds randomness or removes it, never knowledge.

    2. Why can pretraining use trillions of tokens while SFT uses far fewer examples?

    Pretraining needs no labels, so it scales with the text available. SFT needs written demonstrations, and since it mostly teaches style, a small careful set is enough.

    3. A team fine-tunes on 500 FAQs and the model now answers confidently on topics outside them. Why?

    It learned the style of confident answers, not new knowledge. Use retrieval for the content.

    4. Which stage taught the model Arabic grammar, and which a polite register?

    Grammar comes from pretraining; register comes mainly from post-training. If pretraining had little Arabic, post-training cannot supply what was never read.

    5. A colleague says "temperature zero, so one test run is enough". What do you say?

    Zero reduces variation but does not guarantee repeatability. Run each case several times and report the spread.
