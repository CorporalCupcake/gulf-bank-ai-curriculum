    Convolutions and Recurrence: Finding Patterns in Space and in Time

    Contents
    Part 1

    The intuition

    A clerk checking a scanned cheque asks the same small questions at every spot: is there an edge here? A stamp? That is a convolution: one small detector slid across the page.

    You reading a sentence word by word do the same: you keep a running impression ("this review is turning negative") and update it with each new word. That is a recurrent network: it reads one event at a time and carries a summary forward.

    Hold onto thisBoth share weights, a convolution across positions and a recurrent network across time steps. That means few parameters and good learning from modest data. The limit: a filter sees only locally, and a memory passed along many steps fades.

    A filter is a question with numbers in it: a big total means "this patch looks like what I am built to find". Real networks learn their filters, from edges early on to parts and objects later.

    Part 2

    How it really works

    Convolution: the operation, and why it is so cheap

    The filter multiplies the pixels under its window by its weights, adds them up and slides on. Because the same few weights are reused everywhere, the parameter count ignores image size. Padding keeps the map's size, stride shrinks it, and pooling keeps "was it there?" while dropping the exact position.

    A colour image has three channels (red, green, blue), and a layer holds many filters, one output channel each. A 3×3 layer taking 3 channels to 16 has just 448 weights, whatever the picture. Padding adds a zero border so the map keeps its size. Stride moves the window several pixels at a time, which shrinks the map and cuts compute. Pooling takes the maximum or average over a small block, so a stamp that moves a few pixels gives the same answer. This is invariance: the output ignores small shifts.

    The knobs that matter are filter size (3×3 is the default; stacking small filters beats one big one), channel count (width, which drives compute) and stride. Each filter's output goes through a nonlinearity such as ReLU, which is what lets stacks learn more than a single linear filter could.

    The saving rests on locality (a pixel is explained by its neighbours) and stationarity (a pattern can appear anywhere). These assumptions help with limited data, but fail for a table of unrelated columns, which is partly why gradient boosting still beats deep nets on tabular data. Such assumptions are inductive biases: they limit what the network can represent, so it generalises better from limited data. Convolutions are also not rotation- or scale-invariant by themselves. Networks learn that from augmented examples, not from the architecture.

    Stacking layers: receptive fields and the feature hierarchy

    The input region that can influence one unit is its receptive field. A plain stack of 3×3 layers grows it slowly, so ten layers see only 21 pixels across. Strides, pooling or dilated filters (spaced with gaps) double the reach per layer.

    Depth builds a hierarchy: edges, then corners and textures, then parts, then whole objects such as a logo or a table. This is why a network trained on millions of photographs transfers well. Its early layers are generic, so you can freeze them and retrain only the last layers on a few thousand cheque images. That is transfer learning, and it is the usual first move in document vision.

    Convolutions beyond photographs

    Anything laid out along a line or grid fits. Slid along a customer's transactions, a 1-D filter can learn "three small charges in a row"; scoring needs it causal, with no peeking at later steps. Stack such layers with growing dilation and you get a temporal convolutional network (TCN), which trains in parallel across the whole sequence and often matches recurrent nets. Statements, cheques and Emirates ID cards are pictures first, so convolutional backbones find text lines, stamps and signatures (B7, A14). The same family spots manipulated faces in eKYC (A3). Voice biometrics and call audio can be turned into time-frequency images and read the same way.

    Recurrent networks: reading one event at a time

    A recurrent neural network (RNN) keeps a hidden state as memory, a running tally rewritten after every event from the old tally plus the new input.

    Training is the trouble. The learning signal passes back through every step and shrinks a little each time, so it all but vanishes after about 30 steps. That is the vanishing gradient. A plain RNN learns short-range structure and struggles to link distant events, which is the very thing it was built for.

    The weights are shared across time steps, just as a filter is shared across positions, so the network handles any sequence length. You can read the state after the last event to score a customer, or after every event for a running risk score. The opposite failure, a signal that grows without limit, is the exploding gradient. Gradient clipping fixes that cheaply. Vanishing is structural and needs a different design.

    LSTM and GRU: gates that protect the memory

    The LSTM adds a cell state updated by adding rather than repeated squashing, like editing lines in a notebook instead of rewriting every page. Learned gates decide what to forget, write and expose, so the signal survives while the forget gate stays open. The GRU is a lighter version with two gates: fewer parameters, usually similar accuracy, and faster to train. A forget gate can hold a "new device" flag for fifty events and drop it when a trusted login arrives. Choose between them empirically; neither wins reliably.

    Practical knobs are hidden size (memory capacity; 32 to 256 is typical for transaction data), number of layers (one or two is enough), dropout, and the length of the training window. Be honest about the limit: "remembers" means "can be trained to use". LSTMs still forget over hundreds of steps, and their recall is weaker than attention's direct lookup. Training also has to be sequential, so it cannot use a GPU as fully as a convolution or transformer can.

    A recurrent model is also a streaming state machine, needing only one small stored vector per customer, which is why it survives in low-latency scoring. Each update costs the same however long the history, so you never re-read old events.

    Why attention displaced both, and where they still win

    Recurrent nets are sequential and squeeze the whole past into one vector. Attention (F5.5) lets every position look directly at every other, which parallelises well but costs more on long sequences. Convolutions stay strong in vision when data is limited (P3). For short customer histories and tight latency, a small GRU, LSTM or TCN is a sensible alternative to a transformer.

    Strengths, limits and when to use it

    Strong at

    • Learning from modest data. Locality and weight sharing mean far fewer parameters to fit, so thousands of labelled images can be enough, especially with a pretrained backbone.
    • Local patterns anywhere in the input. One filter finds a stamp, a spike or a burst of small charges wherever it occurs, with no need to see each position in training.
    • Speed and cheap compression. Convolutions are fully parallel and map well to GPUs and phones, and they quantise and prune well (P3).
    • Streaming scoring (recurrent nets). One small state per customer and constant work per event suits real-time card authorisation.
    • Variable-length sequences. A recurrent net takes 3 events or 300 with the same weights.

    Weak at, or don't use when

    • Tabular data. Columns have no neighbours, so locality is a false assumption. Use gradient boosting.
    • Long-range links. A convolution sees only its receptive field, and a plain RNN forgets beyond about 30 steps. LSTMs stretch that, but not to hundreds.
    • Global context. Understanding a whole document layout or a long conversation needs attention, which looks at everything directly.
    • Very little data and no pretrained model. A deep net trained from scratch on 500 samples will memorise them.
    • Explanations regulators will read. Filters and hidden states are hard to explain. Occlusion maps help but are weaker evidence than a scorecard's reason codes.

    Alternatives and how to choose

    OptionPick it whenAvoid when

    TCN (causal 1-D CNN)Fixed-length windows of recent events; fast parallel training; stable resultsThe signal sits beyond its receptive field, or histories vary widely in length
    GRU or LSTMStreaming per-customer state; short to medium histories; small team and tight latencyVery long sequences, or you want to train fast on big GPUs

    In practice

    Try first: a boosted-tree baseline on aggregate features (counts and amounts over 1 hour, 1 day and 30 days). Move to a sequence model only if it clearly beats that on a customer-grouped, forward-in-time split. For images, start from a pretrained backbone and fine-tune; training from scratch is rarely worth it.

    Defaults and knobs: 3×3 filters, dilation doubling per layer (1, 2, 4, 8) and causal padding for TCNs; a one- or two-layer GRU with hidden size around 64 and gradient clipping for recurrent models. Receptive field and hidden size are the knobs that matter most. Check the receptive field before you tune anything else.

    Scale: fine-tuning a document CNN needs a few thousand labelled images and a single GPU. A sequence model on transactions wants hundreds of thousands of customers with fraud labels, and fraud is rare, so expect to weight or resample.

    In banking: CNN backbones sit under cheque, ID and statement processing and eKYC liveness checks. GRU or TCN models score card or payment sequences next to a boosted-tree model, usually as an extra feature or an ensemble member rather than a replacement. Forecasting and chat assistants have mostly moved to transformers.

    Part 3

    How it fails, and how to spot it

    • A sequence model that peeks at the future

      Symmetric padding or a bidirectional layer lets the model see later events. Offline AUC looks superb; live, it collapses.

      Spot itPerturb a later event in a test and see whether the output at time t changes.
    • Weak evaluation

      Splitting by transaction puts the same cardholder in train and test, and a deep model without a boosted-tree baseline may not justify its serving cost.

      Spot itCheck card IDs across the split, the test period (F4.3) and the baseline.
    • Receptive field shorter than the pattern

      The fraud signature spans 80 events; the network sees 15.

      Spot itWork out the receptive field from the layer settings, as in Simulation 3.
    • Shortcut learning and format shift

      A cheque classifier learns the scanner's border, not the forged signature, or meets angled phone photos after training on clean scans.

      Spot itTest on scans from another branch, scanner or channel, and occlude regions to see what drives the output.
    • Training on too few fraud cases

      With a fraud rate under 0.1%, a sequence model can learn to say "legitimate" always and still look accurate. Or it memorises the handful of positives it saw.

      Spot itLook at precision and recall at a fixed alert volume, not accuracy, and compare with the baseline on the same alerts.
    • Stale state and padding

      Stored state comes from an old model version, or padding is treated as real events.

      Spot itVersion the state with the model and check that padding differently does not change the score.
    Part 4

    Self-check

    Answer before opening.

    1. Why does a convolutional layer's parameter count not depend on image size?

    The same small filter is reused at every position, so a bigger image means more positions, not more weights.

    2. Would a deeper stack of 3×3 layers find a pattern spread over 100 transactions? What would you check?

    The receptive field. A plain stack grows by two steps per layer, so it needs about 50 layers. Strides or dilation double reach per layer.

    3. Why does a plain RNN struggle to link an event 30 steps back, and how does a gated cell help?

    The learning signal shrinks at every step on the way back. A gated cell updates its memory by adding, so the signal survives while the forget gate stays near 1.

    4. A 1-D conv fraud model with symmetric padding scores brilliantly offline. What is likely wrong?

    It sees later events, including the fraud itself. Use causal padding and re-test.

    5. When would you choose a GRU or TCN over a transformer for transaction data?

    With short histories, strict latency, modest data and a small per-customer state, and only if it beats a boosted-tree baseline under a customer-grouped, forward-in-time split.

    6. You have 200,000 customers with 18 months of card history and a working boosted-tree model. Would you add a GRU, a TCN or a transformer? Why?

    Try a GRU or TCN first, as an extra model whose output feeds the boosted-tree model or an ensemble. The data is large enough for it, latency is likely tight, and histories are short. A transformer adds cost and only pays off with much more data or long context. Keep the boosted-tree model as the baseline.
