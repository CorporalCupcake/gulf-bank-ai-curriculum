    Convolutions and Recurrence: Finding Patterns in Space and in Time

    How a small sliding filter finds edges, stamps and local patterns in images and sequences with a tiny number of weights, how a recurrent network carries memory from one event to the next, and why one of them faded while the other quietly stayed in production.

    Contents

    The whole lesson in one sentenceA convolution reuses one small detector at every position, so it learns local patterns cheaply but sees only as far as its stack of layers reaches, while a recurrent network reads events one by one and carries a state forward, which gives it unlimited reach in theory and a fading memory in practice.

    Part 1

    The intuition

    A clerk checking a scanned cheque asks the same small questions at every spot: is there a straight edge here? A curve? A stamp? That is a convolution: one small detector slid across the page and asked at every position.

    A fraud analyst reading a card history works differently. She reads in order: three AED 1 charges at an online shop, then AED 4,800 twenty minutes later. She keeps a running impression ("this card is being tested") and updates it line by line. That is a recurrent network: it reads one event at a time and carries a summary forward.

    Both avoid relearning the same structure. A stamp is a stamp wherever it sits; a burst of small charges means the same on Tuesday as on Friday. A fully connected network (F5.1) would learn "stamp top-left" and "stamp centre" as separate facts. These designs build the repetition in, so the pattern is learned once.

    Hold onto thisBoth share weights. A convolution shares one filter across positions; a recurrent network shares one set of weights across time steps. That means few parameters and good generalisation from modest data. It also sets the limits: a filter sees only locally, and a memory passed along many steps fades.
    • A filter is a question with numbers in it. Multiply each pixel under the window by its weight and add. A big positive total means "this patch looks like what I am built to find"; near zero means it does not.
    • The output is a map of where the answer was "yes". It is not a smaller copy of the image. Knowing where a feature sits lets later layers combine features into shapes.
    • Real networks learn their filters. They start random and backpropagation (F5.1, F1.3) shapes them. Early filters become edges and colour blobs; later ones respond to textures, parts, then objects, or in documents, to rules, boxes and stamps.
    Part 2

    How it really works

    Convolution: the operation, and why it is so cheap

    For a 2-D input X and a k×k filter K, the output at row r, column c is below. (Libraries strictly compute cross-correlation, with no filter flip. Since the filter is learned, the difference is invisible.)

    Y[r,c]=∑i,jK[i,j]·X[r+i,c+j]+b

    Multiply the window element by element, add, add a bias b, then apply a nonlinearity such as ReLU (F5.1). With input side n, padding p per edge, filter size k and stride s, the output side is ⌊(n + 2p − k) ÷ s⌋ + 1. In Simulation 1: (10 + 0 − 3) ÷ 1 + 1 = 8.

    • Channels. A colour image has three (red, green, blue). A filter is k×k×(input channels) numbers, and a layer holds many filters, one output channel each. 3 channels in, 3×3 filters, 16 out: 3·3·3·16 + 16 = 448 parameters, whatever the image size.
    • Padding. A border of zeros so the output keeps the input's size. Without it, maps shrink each layer and edge pixels are seen less.
    • Stride. Moving two pixels at a time halves the map and cuts compute fourfold. It is how networks lower resolution with depth.
    • Pooling. Replace each block by its max or mean: exact position is lost, "was it there?" is kept. Modern nets often use strided convolutions instead.
    • Translation equivariance. Move the stamp and the bright spot in the map moves with it. Pool over all positions and the answer becomes invariant: "there is a stamp somewhere".

    The saving rests on two assumptions that hold for images and many documents: locality (a pixel is explained by its neighbours) and stationarity (a pattern can appear anywhere). Such assumptions are inductive biases: they shrink what the network can represent, so it generalises better from limited data. Like reading a map with a fixed-size magnifier, it works only if neighbours matter. For a table of unrelated columns they do not, which is partly why gradient boosting still beats deep nets on tabular data.

    Stacking layers: receptive fields and the feature hierarchy

    One 3×3 filter sees a 3×3 patch. A second 3×3 layer on top sees a 5×5 patch of the original, since its window covers three overlapping first-layer windows. The input region that can influence one unit is its receptive field. For plain stride-1 layers it grows by k − 1 per layer:

    RF(L)=1+L·(k−1)

    L layers of filter size k. Ten 3×3 layers see only 21 pixels across. If each layer halves the resolution (stride 2, pooling) or the filters are dilated (spaced with gaps), reach doubles per layer: RF = 1 + (k − 1)(2L − 1). Ten such layers see 2,047 pixels.

    Depth builds a hierarchy. Early layers detect edges, middle layers combine them into corners and textures, late layers respond to whole objects such as a logo, signature block or table. Depth is how the network reaches far enough to see context.

    The same arithmetic holds in one dimension: a 1-D conv stack over a customer's transactions sees only as many past events as its receptive field covers.

    Convolutions beyond photographs

    Anything laid out along a line or grid, where neighbours belong together and patterns repeat, fits.

    • 1-D convolutions on sequences. Slide a filter along a customer's transactions (amount, merchant category, time gap as channels). It can learn "three small charges in a row" or "new country, then a large amount". All positions run in parallel, so training is fast. Stacking with growing dilation gives the temporal convolutional network (TCN), which Bai, Kolter and Koltun (2018) showed matching or beating standard recurrent nets on many benchmarks. For scoring, the convolution must be causal (no peeking at later steps).
    • Text. Character-level convolutions catch prefixes, suffixes and spelling patterns without a vocabulary: useful for noisy names, Arabic names transliterated in Latin script, and OCR garbage. A pretrained transformer (F5.5) is now the usual choice.
    • Document images. Statements, cheques, Emirates ID cards and trade documents are pictures first. Convolutional backbones find text lines, tables, stamps and signatures; layout models then read the text. Right-to-left Arabic, mixed Arabic-English fields and diacritics make this harder than Latin-only benchmarks suggest (B7, A14).
    • Signals and spectrograms. Voice biometrics and call audio become time-frequency images for convolutional nets. The same family spots tampered images and manipulated faces in eKYC (A3).
    • Autoencoders. Convolutional autoencoders compress and reconstruct images; high reconstruction error flags oddities (F4.4).

    In code: PyTorch reads (batch, channels, length), so 32 customers with 200 transactions of 6 features each go in as (32, 6, 200).

    import torch.nn as nn

# Causal 1-D conv: pad only on the left so step t never sees step t+1.
class CausalConv(nn.Module):
    def __init__(self, c_in, c_out, k, dilation=1):
        super().__init__()
        self.pad = (k - 1) * dilation
        self.conv = nn.Conv1d(c_in, c_out, k, dilation=dilation)
    def forward(self, x):                      # x: (batch, channels, time)
        x = nn.functional.pad(x, (self.pad, 0))
        return self.conv(x).relu()

    Recurrent networks: reading one event at a time

    A convolution has a fixed window; a recurrent neural network (RNN) has none. It keeps a vector h, the hidden state, as memory, like a running tally that is rewritten after every event from the old tally plus the new input:

    ht=tanh(Wht−1+Uxt+b)

    xt is the event at step t (amount, merchant type, time gap). W, U and b are the same at every step, the time-axis version of a shared filter. Read h after the last event to score a customer, or after every event for a running risk score.

    Training uses backpropagation through time: unroll the loop into a very deep network, one layer per step with shared weights, and run backprop (F5.1) through it. The trouble starts here. To learn that an event 30 steps ago mattered, the learning signal passes back through 30 copies of W, each time multiplied by roughly W times the slope of tanh. The signal from step T back to step k is a product:

    ∂hT∂hk=∏j=k+1TW·tanh′(·)

    Shown for one number; in a real network W is a matrix and its largest singular value governs the product. Factors below 1 shrink the signal geometrically: 0.6 multiplied 30 times is 2 × 10−7. That is the vanishing gradient. Factors above 1 blow it up: the exploding gradient. Clipping fixes explosion; vanishing is structural.

    So a vanilla RNN learns short-range structure and struggles to link distant events, the very thing it was built for. Bengio, Simard and Frasconi (1994) analysed why; Hochreiter's 1991 thesis found it first.

    LSTM and GRU: gates that protect the memory

    Hochreiter and Schmidhuber (1997) added a second channel, the cell state c, updated by adding rather than repeated squashing. Think of a notebook where you edit lines instead of rewriting every page:

    ct=ft⊙ct−1+it⊙gt

    The forget gate f (0 to 1, computed from input and state) sets how much old memory to keep. The input gate i sets how much of the new candidate g to write. An output gate sets how much memory to expose as h. ⊙ is element-wise multiplication. With f near 1, the gradient along the cell state is a product of numbers near 1, so it survives many steps.

    The GRU (Cho et al., 2014) merges these into two gates and one state: fewer parameters, often the same accuracy. LSTM versus GRU rarely matters as much as the data and features.

    Gates are learned and input-dependent, so the network learns what to remember. A forget gate can hold a "new device" flag for fifty events and drop it when a trusted login arrives.

    • "Remembers" means "can be trained to use". The simulation shows gradients, which decide what the network can learn. LSTMs still forget over hundreds of steps, and recall stays weaker than attention's direct lookup.
    • A recurrent model is a streaming state machine. To score the next event you need only the stored state h and the new event, not the full history. Memory per customer is one small vector and each update costs the same however long the history. That is why recurrent ideas survive in low-latency scoring.

    Why attention displaced both, and where they still win

    Recurrent nets have two more weaknesses. They are sequential: step 100 waits for step 99, so GPU training is slow. And memory is a bottleneck: the whole past is squeezed into one vector. Attention (F5.5), added to recurrent translation models by Bahdanau et al. (2014) and made the whole architecture by Vaswani et al. (2017), lets every position look directly at every other. It parallelises and has no bottleneck, but cost grows with the square of sequence length.

    • Vision. Vision transformers (Dosovitskiy et al., 2020) beat convnets on large datasets, but modernised convnets such as ConvNeXt (Liu et al., 2022) closed most of the gap. Convolutions are cheaper, easier to compress (P3) and strong with limited data, so they stay normal for on-device or high-throughput vision.
    • Sequences. For short per-customer histories, tight latency and small training sets, a small GRU, LSTM or TCN is a sensible alternative to a transformer.
    • Recurrence returns. State-space models such as Mamba (Gu and Dao, 2023) and xLSTM (Beck et al., 2024) go back to a fixed-size running state with linear cost.
    Part 3

    How it fails, and how to spot it

    Each failure comes with its quickest check.

    • A sequence model that peeks at the future

      A convolution with symmetric padding, a bidirectional recurrent layer, or a window that includes the target transaction. Offline AUC looks superb; live, it collapses.

      Spot itAsk whether the model is causal: could the output at time t change if you altered an event after t? Perturb a later event in a test and see.
    • Splitting by transaction instead of by customer and time

      The same cardholder's sequences appear in train and test, so the model memorises customers.

      Spot itCheck for customer or card IDs on both sides of the split, and whether the test period is later than the training period (F4.3).
    • Skipping the tabular baseline

      A deep sequence model reported with no comparison to a boosted tree on window aggregates.

      Spot itAsk for the baseline and its score on the same split. Gains of a point or two may not justify the cost of serving the state.
    • Receptive field shorter than the pattern

      The fraud signature spans 80 events; the network sees 15.

      Spot itCompute the receptive field from the layer settings, as in Simulation 3. If the signal is further back than it, no amount of training will find it.
    • Shortcut learning in images

      A cheque classifier learns the scanner's border or the branch's stamp colour, not the forged signature. A conv net happily uses any local cue that predicts the label.

      Spot itTest on scans from a different branch, scanner or month. Look at saliency maps or occlude regions to see what drives the output.
    • Resolution and format shift

      Trained on clean 300 dpi scans, deployed on phone photos at an angle, in poor light, with a thumb in the corner.

      Spot itEvaluate on a sample of real production inputs. Check performance by capture channel (branch, ATM, mobile app) and by language and script.
    • State drift in streaming recurrent models

      The stored hidden state was computed with an old model version, or after a gap in the feed, and silently disagrees with what the new model expects.

      Spot itVersion the stored state with the model. Replay a customer's full history and compare with the streamed state; they should match.
    • Variable lengths and padding handled badly

      Customers with 3 events and customers with 3,000 are padded or truncated, and the padding is treated as real events.

      Spot itCheck for masking. Score a customer with their history padded differently: the answer should not change.
    • Adversarial and manipulated inputs

      Small, deliberate pixel changes fool image classifiers; a forged document is touched up to pass; a fraudster spaces transactions to keep under the learned pattern.

      Spot itInclude adversarial and re-captured samples in testing, and do not let one model be the only control (G1).
    Part 4

    Self-check

    Answer before opening. The numeric ones need only Part 2.

    1. A 64×64 greyscale image goes through a 5×5 filter with no padding and stride 1. What is the output size, and how many weights does the filter have?

    Output side = (64 + 0 − 5) ÷ 1 + 1 = 60, so 60×60. The filter has 25 weights (plus one bias), reused at all 3,600 positions.

    2. A convolutional layer takes 8 input channels and produces 32, with 3×3 filters. How many parameters, including biases?

    3 × 3 × 8 × 32 = 2,304 weights, plus 32 biases, so 2,336. It does not depend on the image size.

    3. You stack six 3×3 convolutions with stride 1. How many input pixels can one output unit see? What if the filters are dilated 1, 2, 4, 8, 16, 32?

    Plain: 1 + 6 × 2 = 13. Dilated doubling: 1 + 2 × (1 + 2 + 4 + 8 + 16 + 32) = 1 + 2 × 63 = 127. Same parameters, ten times the reach.

    4. The recurrent factor in a plain RNN averages 0.7 per step. Roughly how much signal reaches 20 steps back? And with a gated cell whose forget gate is 0.98?

    0.720 ≈ 0.0008, so about 0.08% of the signal. Gated: 0.9820 ≈ 0.67, about two thirds. That is the whole argument for gating.

    5. A fraud team's 1-D conv model uses symmetric padding and scores brilliantly offline. What is likely wrong?

    Symmetric ("same") padding with centred filters lets each output depend on later events as well as earlier ones, so the model sees the future, including the fraudulent transaction itself. Use causal padding (left only) and re-test.

    6. Why can a convolutional network find a stamp anywhere on a cheque with a few hundred labelled examples, when a fully connected one would need far more?

    The convolution ties one stamp detector across all positions, so every example teaches it at every location, and its parameter count is tiny. The fully connected model must learn the stamp separately at each position it might appear, with millions of free weights, so it needs examples of each.

    7. When would you choose a GRU or TCN over a transformer for transaction data?

    Short histories (tens to a few hundred events), a strict latency or memory budget at scoring time, modest training data, and a need to keep a small per-customer state. And as always, only if it beats a boosted-tree baseline on aggregate features under a customer-grouped, forward-in-time split.
