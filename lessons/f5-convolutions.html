    Convolutions and Recurrence: Finding Patterns in Space and in Time

    How a small sliding filter finds edges, stamps and local patterns in images and sequences with a tiny number of weights, how a recurrent network carries memory from one event to the next, and why one of them faded while the other quietly stayed in production.

    Contents

    The whole lesson in one sentenceA convolution reuses one small detector at every position, so it learns local patterns cheaply but sees only as far as its stack of layers reaches, while a recurrent network reads events one by one and carries a state forward, which gives it unlimited reach in theory and a fading memory in practice.

    Part 1

    The intuition

    A clerk checking a scanned cheque asks the same small questions at every spot: is there an edge here? A stamp? That is a convolution: one small detector slid across the page and asked at every position.

    A fraud analyst reading a card history works differently. She reads in order: three AED 1 charges, then AED 4,800 twenty minutes later. She keeps a running impression ("this card is being tested") and updates it line by line. That is a recurrent network: it reads one event at a time and carries a summary forward.

    Both build the repetition in. A stamp is a stamp wherever it sits, so the pattern is learned once, not separately for "top-left" and "centre" as a fully connected network (F5.1) would.

    Hold onto thisBoth share weights: a convolution across positions, a recurrent network across time steps. That means few parameters and good learning from modest data. It also sets the limits: a filter sees only locally, and a memory passed along many steps fades.
    • A filter is a question with numbers in it. A big positive total means "this patch looks like what I am built to find"; near zero means it does not.
    • The output is a map of where the answer was "yes". Knowing where a feature sits lets later layers combine features into shapes.
    • Real networks learn their filters. Early ones become edges; later ones respond to textures, parts, then objects, or in documents, to boxes and stamps.
    Part 2

    How it really works

    Convolution: the operation, and why it is so cheap

    The filter multiplies the pixels under the window by its weights, adds them up, and passes the result through a nonlinearity. Because the same few weights are reused everywhere, the parameter count ignores image size: a 3×3 layer taking 3 colour channels to 16 has just 448, whatever the picture.

    • Channels. A colour image has three. A layer holds many filters, one output channel each.
    • Padding and stride. Padding adds a zero border so the map keeps its size. Stride moves the window several pixels at a time, shrinking the map.
    • Pooling and invariance. Pooling keeps "was it there?" and drops exact position. Move the stamp and the bright spot in the map moves with it; pool over all positions and the answer becomes "there is a stamp somewhere".

    The saving rests on two assumptions: locality (a pixel is explained by its neighbours) and stationarity (a pattern can appear anywhere). Such assumptions are inductive biases: they limit what the network can represent, so it generalises better from limited data. They fail for a table of unrelated columns, which is partly why gradient boosting still beats deep nets on tabular data.

    Stacking layers: receptive fields and the feature hierarchy

    One 3×3 filter sees a 3×3 patch. A second 3×3 layer on top sees a 5×5 patch of the original. The input region that can influence one unit is its receptive field. A plain stack grows slowly: ten 3×3 layers see only 21 pixels across. If each layer halves the resolution (stride 2, pooling) or the filters are dilated (spaced with gaps), reach doubles per layer instead.

    Depth builds a hierarchy: edges, then corners and textures, then whole objects such as a logo or table. In one dimension, a conv stack over transactions sees only as many past events as its receptive field covers.

    Convolutions beyond photographs

    Anything laid out along a line or grid, where neighbours belong together, fits.

    • 1-D convolutions on sequences. Slide a filter along a customer's transactions. It can learn "three small charges in a row" or "new country, then a large amount". Stacking with growing dilation gives the temporal convolutional network (TCN), which trains fast and often matches recurrent nets. For scoring, the convolution must be causal: no peeking at later steps.
    • Document images. Statements, cheques and Emirates ID cards are pictures first. Convolutional backbones find text lines, tables, stamps and signatures; layout models then read the text. Right-to-left Arabic and mixed-language fields make it harder than benchmarks suggest (B7, A14).
    • Signals and spectrograms. Voice biometrics and call audio become time-frequency images. The same family spots manipulated faces in eKYC (A3).
    import torch.nn as nn

# Causal 1-D conv: pad only on the left so step t never sees step t+1.
class CausalConv(nn.Module):
    def __init__(self, c_in, c_out, k, dilation=1):
        super().__init__()
        self.pad = (k - 1) * dilation
        self.conv = nn.Conv1d(c_in, c_out, k, dilation=dilation)
    def forward(self, x):                      # x: (batch, channels, time)
        x = nn.functional.pad(x, (self.pad, 0))

    Recurrent networks: reading one event at a time

    A convolution has a fixed window; a recurrent neural network (RNN) has none. It keeps a vector, the hidden state, as memory: a running tally rewritten after every event from the old tally plus the new input. The same weights are used at every step, the time-axis version of a shared filter. Read the state after the last event to score a customer, or after every event for a running risk score.

    The trouble comes in training. To learn that an event 30 steps ago mattered, the learning signal passes back through 30 steps, shrinking a little at each. Shrink by 0.6 thirty times and almost nothing is left. That is the vanishing gradient; the opposite, a signal that grows without limit, is the exploding gradient. Clipping fixes explosion; vanishing is structural.

    So a vanilla RNN learns short-range structure and struggles to link distant events, the very thing it was built for.

    LSTM and GRU: gates that protect the memory

    The LSTM adds a second channel, the cell state, updated by adding rather than repeated squashing. Think of a notebook where you edit lines instead of rewriting every page. Learned gates decide what to forget, what to write and what to expose. While the forget gate stays near 1, the learning signal survives many steps.

    The GRU merges these into two gates: fewer parameters, often the same accuracy. A forget gate can hold a "new device" flag for fifty events and drop it when a trusted login arrives.

    • "Remembers" means "can be trained to use". LSTMs still forget over hundreds of steps, and recall stays weaker than attention's direct lookup.
    • A recurrent model is a streaming state machine. To score the next event you need only the stored state and the new event. Memory per customer is one small vector and each update costs the same however long the history, which is why recurrence survives in low-latency scoring.

    Why attention displaced both, and where they still win

    Recurrent nets are sequential (step 100 waits for step 99) and squeeze the whole past into one vector. Attention (F5.5) lets every position look directly at every other. It parallelises and has no bottleneck, but costs more as sequences grow.

    • Vision. Vision transformers beat convnets on large datasets, but modern convnets closed most of the gap. Convolutions are cheaper, easier to compress (P3) and strong with limited data.
    • Sequences. For short per-customer histories, tight latency and small training sets, a small GRU, LSTM or TCN is a sensible alternative to a transformer.
    Part 3

    How it fails, and how to spot it

    Each failure comes with its quickest check.

    • A sequence model that peeks at the future

      A convolution with symmetric padding, a bidirectional recurrent layer, or a window that includes the target transaction. Offline AUC looks superb; live, it collapses.

      Spot itAsk whether the output at time t could change if you altered an event after t. Perturb a later event in a test and see.
    • Weak evaluation: leaky splits and no baseline

      Splitting by transaction lets the same cardholder appear in train and test, so the model memorises customers. And a deep sequence model reported without a boosted-tree baseline may not justify its serving cost.

      Spot itCheck for card IDs on both sides of the split and that the test period is later (F4.3). Ask for the baseline score on the same split.
    • Receptive field shorter than the pattern

      The fraud signature spans 80 events; the network sees 15.

      Spot itWork out the receptive field from the layer settings, as in Simulation 3. If the signal is further back, no amount of training will find it.
    • Shortcut learning and format shift in images

      A cheque classifier learns the scanner's border or the branch's stamp colour, not the forged signature. Or it is trained on clean scans and deployed on angled phone photos.

      Spot itTest on scans from a different branch, scanner or month, and by capture channel and script. Occlude regions to see what drives the output.
    • Stale state and badly handled lengths

      A streaming model's stored state was computed by an old model version or after a gap in the feed. Or short histories are padded and the padding is treated as real events.

      Spot itVersion the state with the model and replay a full history to compare. Check masking: padding differently should not change the score.
    • Adversarial and manipulated inputs

      Small pixel changes fool image classifiers; a forged document is touched up to pass; a fraudster spaces transactions to stay under the learned pattern.

      Spot itInclude adversarial and re-captured samples in testing, and do not let one model be the only control (G1).
    Part 4

    Self-check

    Answer before opening.

    1. Why does a convolutional layer's parameter count not depend on the image size?

    The same small filter is reused at every position, so only the filter size and the number of channels matter. A bigger image just means more positions, not more weights.

    2. A colleague says a deeper stack of 3×3 layers will find a fraud pattern spread over 100 transactions. What would you check?

    The receptive field. A plain stack grows by only two steps per layer, so it needs about 50 layers. Strides or dilation make reach double per layer, with the same parameters.

    3. Why does a plain RNN struggle to link an event 30 steps back to today's outcome, and how does a gated cell help?

    The learning signal shrinks at every step on its way back, so almost nothing arrives. A gated cell updates its memory by adding, and while the forget gate stays near 1 the signal survives. That is the whole argument for gating.

    4. A fraud team's 1-D conv model uses symmetric padding and scores brilliantly offline. What is likely wrong?

    Symmetric padding lets each output depend on later events as well as earlier ones, so the model sees the future, including the fraud itself. Use causal padding (left only) and re-test.

    5. Why can a convolutional network find a stamp anywhere on a cheque with a few hundred labelled examples, when a fully connected one would need far more?

    The convolution ties one stamp detector across all positions, so every example teaches it everywhere, and it has few weights. The fully connected model must learn the stamp separately at each position.

    6. When would you choose a GRU or TCN over a transformer for transaction data?

    Short histories, a strict latency or memory budget, modest training data, and a need for a small per-customer state. And only if it beats a boosted-tree baseline on aggregate features under a customer-grouped, forward-in-time split.
