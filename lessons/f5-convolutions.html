    Convolutions and Recurrence: Finding Patterns in Space and in Time

    How a small sliding filter finds edges, stamps and local patterns in images and sequences with a tiny number of weights, how a recurrent network carries memory from one event to the next, and why one of them faded while the other quietly stayed in production.

    Contents

    The whole lesson in one sentenceA convolution reuses one small detector at every position, so it learns local patterns cheaply but sees only as far as its stack of layers reaches, while a recurrent network reads events one by one and carries a state forward, which gives it unlimited reach in theory and a fading memory in practice.

    Part 1

    The intuition

    A clerk checks a scanned cheque. She does not stare at the whole page at once. Her eye lands on the amount box, then the signature, then the date, and at each spot she asks the same small questions: is there a straight edge here? A curve? A stamp? The questions are the same wherever she looks. That is a convolution: one small detector, slid across the page, asked at every position.

    Now picture a fraud analyst reading a customer's card history. She does not read it as a picture. She reads it in order: three tiny AED 1 charges at an online shop, then a AED 4,800 purchase twenty minutes later. What matters is the order and what came before. She keeps a running impression ("this card is being tested") and updates it with each new line. That is a recurrent network: it reads one event at a time and carries a summary forward.

    Both ideas are about the same thing, which is structure you should not have to relearn. A stamp is a stamp wherever it sits on the page. A burst of small charges means the same thing on Tuesday as on Friday. A plain fully connected network (F5.1) would learn "stamp in the top-left corner" and "stamp in the middle" as two separate facts, and would need examples of each. Convolutions and recurrence build the repetition into the architecture so the model learns the pattern once.

    Hold onto thisBoth are about sharing weights. A convolution shares one filter across positions. A recurrent network shares one set of weights across time steps. Sharing is why they have few parameters, why they generalise from modest data, and also where their limits come from: a filter only sees locally, and a memory passed along many steps fades.

    Three things to take from the picture.

    • The filter is a question with numbers in it. Multiply each pixel under the window by the matching filter weight and add. A big positive total means "this patch looks like what I am built to find". A total near zero means it does not.
    • The output is a map of where the question was answered "yes". It is not a smaller copy of the image. It says where the feature is, which is what lets later layers combine features into shapes.
    • A real network does not choose its filters. It starts them random and uses backpropagation (F5.1, F1.3) to shape them until they help the task. Early filters usually end up as edges and colour blobs. Later ones respond to textures, then parts, then objects or, in documents, to rules, boxes and stamps.
    Part 2

    How it really works

    Convolution: the operation, and why it is so cheap

    Strictly, deep learning libraries compute cross-correlation (no flipping of the filter), but everyone calls it convolution and since the filter is learned the difference is invisible. For a 2-D input X and a filter K of size k×k, the output at row r, column c is:

    Y[r,c]=∑i,jK[i,j]·X[r+i,c+j]+b

    Slide the window to (r, c), multiply element by element, add, add a bias b. A nonlinearity such as ReLU (F5.1) follows. With an input of side n, padding p on each edge, filter size k and stride s, the output side is ⌊(n + 2p − k) ÷ s⌋ + 1. In Simulation 1: (10 + 0 − 3) ÷ 1 + 1 = 8.

    The vocabulary you need, and what each piece does:

    • Channels. A colour image has three input channels (red, green, blue). A filter is really k×k×(input channels) numbers, and a layer holds many filters, each producing one output channel. A layer with 3 input channels, 3×3 filters and 16 output channels has 3·3·3·16 + 16 = 448 parameters, whatever the image size.
    • Padding. Adding a border of zeros so the output keeps the input's size ("same" padding). Without it, each layer shrinks the map and edge pixels are seen fewer times.
    • Stride. Moving the window two pixels at a time halves the map and cuts compute fourfold. It is how networks reduce resolution as they go deeper.
    • Pooling. Replace each small block by its maximum or mean. It throws away exact position and keeps "was it there?". Modern networks often use strided convolutions instead.
    • Translation equivariance. Move the stamp and the feature map's bright spot moves with it. After a final pooling over all positions the answer becomes invariant: "there is a stamp somewhere".

    The saving is the whole reason convolutional nets exist. It comes from two assumptions that happen to be true of images and of many documents: locality (a pixel is best explained by its neighbours) and stationarity (the same pattern can appear anywhere). These are called inductive biases. They shrink the space of functions the network can represent, so with limited data it generalises better than a model that could in principle learn anything. When the assumptions are wrong, as they are for a table of unrelated columns, the bias hurts, which is partly why gradient boosting still beats deep nets on tabular data.

    Stacking layers: receptive fields and the feature hierarchy

    One 3×3 filter sees a 3×3 patch. Stack a second 3×3 layer on top and each of its outputs depends on a 5×5 patch of the original, because its window covers three first-layer outputs which each covered three pixels, overlapping. This region of the input that can influence one unit is its receptive field. For plain stride-1 layers it grows by k − 1 per layer:

    RF(L)=1+L·(k−1)

    L layers of filter size k. Ten 3×3 layers see only 21 pixels across. If each layer also halves the resolution (stride 2, or pooling), or if the filters are dilated (spaced apart, with gaps), the reach doubles each layer instead: RF = 1 + (k − 1)(2L − 1). Ten layers of that see 2,047 pixels.

    This is why deep conv nets build a hierarchy. Early layers, with small receptive fields, detect edges. Middle layers combine them into corners, strokes and textures. Late layers, with large fields, respond to whole objects: a logo, a signature block, a table. Deeper is not decoration, it is how the network reaches far enough to see context.

    The same arithmetic applies in one dimension, over a sequence, which matters for the next topic: a stack of 1-D convolutions over a customer's transactions sees only as many past events as its receptive field covers.

    Convolutions beyond photographs

    Nothing in the operation needs pixels. Anything laid out along a line or a grid, where nearby values belong together and patterns repeat, fits.

    • 1-D convolutions on sequences. Slide a filter along a customer's transactions, with features like amount, merchant category and time gap in the channels. A filter can learn "three small charges in a row" or "a new country followed by a large amount". These run in parallel over all positions, so they train fast. Stacking them with growing dilation gives the temporal convolutional network (TCN), shown by Bai, Kolter and Koltun (2018) to match or beat standard recurrent networks on many sequence benchmarks. Making the convolution causal (no peeking at future steps) is essential for any scoring task.
    • Text. Character-level convolutions find prefixes, suffixes and spelling patterns without a vocabulary. That is useful for noisy names, transliteration variants of Arabic names in Latin script, and OCR garbage, though today a pretrained transformer (F5.5) is the usual choice.
    • Document images. Scanned statements, cheques, Emirates ID cards and trade documents are pictures first. Convolutional backbones find text lines, tables, stamps, signatures and handwriting; layout models then read the text in position. Right-to-left Arabic script, mixed Arabic and English fields and diacritics make these pipelines harder than the Latin-only benchmarks suggest (B7, A14).
    • Signals and spectrograms. Voice biometrics and call-centre audio are often turned into time-frequency images and given to convolutional networks. The same family spots tampered images and manipulated faces in eKYC (A3).
    • Autoencoders. Convolutional autoencoders learn to compress and reconstruct images, and the reconstruction error flags oddities (F4.4).

    A short sketch of what this looks like in code. PyTorch reads data as (batch, channels, length), so a batch of 32 customers, each with their last 200 transactions described by 6 features, goes in as (32, 6, 200):

    import torch.nn as nn

# Causal 1-D conv: pad only on the left so step t never sees step t+1.
class CausalConv(nn.Module):
    def __init__(self, c_in, c_out, k, dilation=1):
        super().__init__()
        self.pad = (k - 1) * dilation
        self.conv = nn.Conv1d(c_in, c_out, k, dilation=dilation)
    def forward(self, x):                      # x: (batch, channels, time)
        x = nn.functional.pad(x, (self.pad, 0))
        return self.conv(x).relu()

    Recurrent networks: reading one event at a time

    A convolution has a fixed window. A recurrent neural network (RNN) has no window at all. It keeps a vector h, the hidden state, which is its memory. At each step it takes the new input and the old state and produces a new state:

    ht=tanh(Wht−1+Uxt+b)

    xt is the event at step t (amount, merchant type, time since the last one). W, U and b are the same weights at every step, the time-axis version of a shared filter. To score a customer you can read off h after the last event, or after every event to give a running risk score.

    Training uses backpropagation through time: unroll the loop into a very deep network, one layer per step, with the same weights in every layer, and run backprop (F5.1) through it. That is where the trouble starts. To learn that an event 30 steps ago mattered, the learning signal has to travel back through 30 copies of W. At each step it is multiplied by roughly W times the slope of tanh. The signal reaching step k from step T is a product:

    ∂hT∂hk=∏j=k+1TW·tanh′(·)

    Written for one number for clarity; in a real network W is a matrix and the size of the product is governed by its largest singular value. If each factor is below 1, the signal shrinks geometrically: 0.6 multiplied 30 times is 2 × 10−7. That is the vanishing gradient. If each factor is above 1 it blows up, the exploding gradient. Gradient clipping fixes the explosion. The vanishing case is structural.

    The consequence is plain: a vanilla RNN learns short-range structure and struggles to link events far apart, which was exactly the thing it was meant to do. Bengio, Simard and Frasconi (1994) analysed why, and Hochreiter's 1991 thesis had already found it.

    LSTM and GRU: gates that protect the memory

    The fix, from Hochreiter and Schmidhuber (1997), is to give the network a second channel, the cell state c, that is updated by adding rather than by repeated squashing:

    ct=ft⊙ct−1+it⊙gt

    The forget gate f (values between 0 and 1, computed from the current input and state) decides how much of the old memory to keep. The input gate i decides how much of the new candidate g to write. An output gate decides how much of the memory to expose as h. ⊙ is element-wise multiplication. If f stays near 1, the gradient along the cell state is a product of numbers near 1, so it survives many steps.

    The GRU (Cho et al., 2014) merges these into two gates and a single state. It has fewer parameters and often performs the same. Choosing between LSTM and GRU rarely matters more than the data and the features.

    The gates are learned and depend on the input, so the network learns what to remember. A forget gate can hold a "this is a new device" flag for fifty events and drop it when a trusted login arrives. Compare the two kinds of memory directly.

    Two practical points follow.

    • "Remembers" means "can be trained to use". The simulation is about gradients, which decide what the network can learn. Gating does not make memory perfect: LSTMs still forget over hundreds of steps, and long-range recall remains weaker than attention's direct lookup.
    • A recurrent model is a streaming state machine. To score a customer's next event you need only their stored state h and the new event, not their full history. Memory per customer is a fixed small vector, and the cost of one update does not grow as the history does. That is a real advantage for low-latency scoring, and it is the main reason recurrent ideas survive.

    Why attention displaced both, and where they still win

    Recurrent networks have two weaknesses beyond fading memory. They are sequential: step 100 cannot be computed until step 99 is done, so they train slowly on GPUs. And their memory is a bottleneck: everything about the past must be squeezed into one vector. Attention (F5.5), introduced as an add-on to recurrent translation models by Bahdanau et al. (2014) and made the whole architecture by Vaswani et al. (2017), lets every position look directly at every other. It parallelises well and has no bottleneck. The price is cost that grows with the square of the sequence length.

    The picture is not one-sided:

    • Vision. Vision transformers (Dosovitskiy et al., 2020) beat convolutional nets on large datasets, but modernised convolutional networks such as ConvNeXt (Liu et al., 2022) closed most of the gap, and convolutions are still cheaper, easier to compress (P3) and strong when data is limited. They remain a normal choice for on-device or high-throughput vision.
    • Sequences. Short per-customer histories, tight latency budgets and small training sets are where a small GRU, LSTM or TCN is a sensible choice against a transformer.
    • Recurrence returns in new clothes. State-space models such as Mamba (Gu and Dao, 2023) and gated recurrent designs like xLSTM (Beck et al., 2024) go back to a fixed-size running state with linear cost, using lessons from both worlds. Part 4 says how far that has got.
    Part 3

    How it connects

    These two architectures sit between the basic network and the attention-based models that now dominate. They also explain choices you will meet in fraud, document and voice systems.

    F5.1 – F5.2 · Neurons, layers, backpropagationThe machinery both reuse

    A convolutional layer is a fully connected layer with most weights forced to zero and the rest tied together. Training a recurrent net is backprop on an unrolled copy.

    F5.5 · AttentionDirect lookup replaces compressed memory

    Attention removes the recurrent bottleneck and the fixed window. Read this next to see what the two designs here were missing.

    F5.6 · Self-supervised and contrastive learningPretraining the backbone

    Modern vision and sequence encoders are pretrained without labels and then fine-tuned, which matters when you have 300 labelled cases.

    F1.3 · GradientsWhy the product of factors matters

    The vanishing and exploding signal is the chain rule applied across many layers or steps. The same applies to very deep convolutional stacks, which residual connections rescued.

    F6 · Overfitting and augmentationFlipping, cropping and noise

    Augmentation is how conv nets get more out of limited images: rotations, crops and scan noise on cheques and IDs.

    F4.4 · Anomaly detectionAutoencoders

    Convolutional and recurrent autoencoders reconstruct images or sequences; high reconstruction error flags the unusual.

    F9 · Time series and forecastingSequences as forecasts

    LSTMs and TCNs are standard deep forecasters, and a well-tuned linear or boosted baseline often matches them.

    F4.3 · ValidationSequence models and time splits

    A customer's events must stay together and the split must run forward in time, or the recurrent state leaks the future (F3.1).

    A8 · Foundation models for transaction dataWhere sequence models are heading

    Large pretrained models over transaction streams are the modern descendant of the recurrent fraud models described here.

    Where it shows up at the bank:

    • Card and payment fraud. Per-card or per-customer recurrent or convolutional sequence models turn a history into features or a running score, usually alongside hand-built aggregates and a boosted-tree model (B1). Their stored state fits a real-time scoring path (P2).
    • Document processing. Cheques, IDs, invoices, bills of lading and letters of credit: convolutional backbones for detection and OCR, layout models on top (B7, A14, A6).
    • eKYC and voice. Face matching, liveness checks and voice verification rely on convolutional encoders. Deepfake detection is an arms race (A3, A9).
    • Behavioural signals. Typing rhythm, touch and mouse traces, and app navigation sequences are short streams where small recurrent or convolutional models are practical (A9).
    • Call-centre analytics. Speech recognition stacks have long used convolutional front-ends and recurrent decoders before moving to attention. Arabic dialects remain a data problem more than an architecture one.
    Part 4

    Where the field is now

    The core ideas are settled and old. The live questions are how much of the work attention-only designs have taken, whether linear-cost recurrent designs can match transformers, and whether, for a bank's own data, any of this beats a good tree model.

    1. 1989–98
      Convolutional nets for handwriting

      LeCun and colleagues trained convolutional networks with backpropagation to read handwritten digits and cheques, deployed in US cheque reading in the 1990s. The architecture still recognisable today.

      LeCun et al., Neural Computation 1989; Proc. IEEE 1998 (from memory)
    2. 1997
      LSTM

      Gated cell state to carry gradients through time, designed to fix the vanishing gradient.

      Hochreiter & Schmidhuber, Neural Computation, 1997
    3. 2012–15
      Deep conv nets take over vision

      AlexNet won ImageNet in 2012 on GPUs. Residual networks (ResNets) in 2015 added skip connections that let nets with over a hundred layers train, the same additive trick as the LSTM cell state.

      Krizhevsky et al., 2012; He et al., CVPR 2016 (from memory)
    4. 2014
      GRU, sequence-to-sequence, and attention

      Recurrent encoder-decoders for translation, then the attention mechanism added to them, the step that led to transformers.

      Cho et al. 2014; Sutskever et al. 2014; Bahdanau et al. 2014
    5. 2018
      Temporal convolutional networks match recurrent ones

      A generic causal, dilated convolutional architecture matched or outperformed LSTMs and GRUs on a range of sequence tasks, with simpler and faster training.

      Bai, Kolter & Koltun, arXiv 1803.01271
    6. 2018–20
      Recurrent models for card fraud

      Academic work on card transactions found LSTMs over a cardholder's history improved on models that saw one transaction at a time, with gains that were largest for card-not-present fraud. Later work on interleaved sequences and learned transaction embeddings followed.

      Jurgovsky et al., Expert Systems with Applications, 2018; Branco et al., KDD 2020 (from memory)
    7. 2020–22
      Vision transformers, then modernised convnets

      Vision transformers showed attention can beat convolutions given enough data. ConvNeXt then re-engineered a ResNet with transformer-era training and design choices and matched transformer accuracy, showing much of the gap was recipe rather than architecture.

      Dosovitskiy et al., ICLR 2021; Liu et al., CVPR 2022
    8. 2022
      Trees still beat deep nets on typical tabular data

      A large benchmark found tree ensembles remained ahead of neural networks, including sequence-style and attention designs, on medium-sized tabular datasets. Relevant to any bank feature table; less so to raw sequences, images or text.

      Grinsztajn, Oyallon & Varoquaux, NeurIPS 2022 (from memory)
    9. 2023–24
      Recurrence comes back with a fixed-size state

      Mamba (a selective state-space model) and xLSTM (an LSTM with exponential gating and matrix memory) aim to match transformer quality with linear cost in sequence length and constant-size inference state. Pure versions still tend to trail comparable transformers on general language benchmarks; hybrids that mix attention with such layers are a common compromise. Secondary sources checked in November 2026 describe a Mamba-3 successor; I did not verify it against the primary paper.

      Gu & Dao, arXiv 2312.00752; Beck et al., NeurIPS 2024 (arXiv 2405.04517)
    10. 2025
      Convolutional students from a giant vision transformer

      DINOv3 trained a very large self-supervised vision transformer, then distilled it into smaller models that include ConvNeXt variants, partly because convolutional nets are cheaper to run and quantise. A sign that convolutions have survived as the deployment-friendly form of the same features.

      Siméoni et al., DINOv3, arXiv 2508.10104

    Part 5

    How it fails, and how to spot it

    These show up in bank analyses and in AI-generated ones. Each comes with the quickest check.

    • A sequence model that peeks at the future

      A convolution with symmetric padding, a bidirectional recurrent layer, or a window that includes the target transaction. Offline AUC looks superb; live, it collapses.

      Spot itAsk whether the model is causal: could the output at time t change if you altered an event after t? Perturb a later event in a test and see.
    • Splitting by transaction instead of by customer and time

      The same cardholder's sequences appear in train and test, so the model memorises customers.

      Spot itCheck for customer or card IDs on both sides of the split, and whether the test period is later than the training period (F4.3).
    • Skipping the tabular baseline

      A deep sequence model reported with no comparison to a boosted tree on window aggregates.

      Spot itAsk for the baseline and its score on the same split. Gains of a point or two may not justify the cost of serving the state.
    • Receptive field shorter than the pattern

      The fraud signature spans 80 events; the network sees 15.

      Spot itCompute the receptive field from the layer settings, as in Simulation 3. If the signal is further back than it, no amount of training will find it.
    • Shortcut learning in images

      A cheque classifier learns the scanner's border or the branch's stamp colour, not the forged signature. A conv net happily uses any local cue that predicts the label.

      Spot itTest on scans from a different branch, scanner or month. Look at saliency maps or occlude regions to see what drives the output.
    • Resolution and format shift

      Trained on clean 300 dpi scans, deployed on phone photos at an angle, in poor light, with a thumb in the corner.

      Spot itEvaluate on a sample of real production inputs. Check performance by capture channel (branch, ATM, mobile app) and by language and script.
    • State drift in streaming recurrent models

      The stored hidden state was computed with an old model version, or after a gap in the feed, and silently disagrees with what the new model expects.

      Spot itVersion the stored state with the model. Replay a customer's full history and compare with the streamed state; they should match.
    • Variable lengths and padding handled badly

      Customers with 3 events and customers with 3,000 are padded or truncated, and the padding is treated as real events.

      Spot itCheck for masking. Score a customer with their history padded differently: the answer should not change.
    • Adversarial and manipulated inputs

      Small, deliberate pixel changes fool image classifiers; a forged document is touched up to pass; a fraudster spaces transactions to keep under the learned pattern.

      Spot itInclude adversarial and re-captured samples in testing, and do not let one model be the only control (G1).
    Part 6

    What to say in the room

    To an executive · 30 seconds
    “Two older building blocks sit under a lot of what we run. The first reads images and scans by looking for small patterns, like edges and stamps, everywhere on the page; it's why we can read cheques and IDs on a phone camera. The second reads a customer's activity in order and keeps a running memory, which helps spot patterns like card testing before a large purchase. Newer models have taken over a lot of this, but the older ones are smaller, faster and cheaper to run, so we choose by the job, and we always compare against a simpler model first.”
    To a technical interviewer or validator
    “A convolution ties one small filter across positions, which cuts parameters and bakes in locality and translation equivariance; its reach is the receptive field, which grows linearly with depth unless you use strides or dilation. A recurrent network ties weights across time and carries a state; vanilla ones fail on long gaps because the backpropagated signal is a product of per-step factors, and gating keeps an additive path open. For transaction streams I'd compare a causal TCN or GRU with a boosted tree on window aggregates, split by customer and forward in time, and only take the sequence model if it adds lift that survives that comparison and the cost of serving state.”
    “Why not just use a transformer for everything?”

    For large pretrained settings, often we do. But attention costs grow with the square of the sequence length, and transformers need data or pretraining to shine. For short customer histories with a tight latency budget, or for on-device image work, a small convolutional or recurrent model is cheaper, easier to explain to a validator and easier to quantise. I'd choose by the constraint and prove it against a baseline.

    “What's the difference between an LSTM and a plain RNN?”

    A plain RNN rewrites its whole memory at each step, so the learning signal shrinks or explodes over long gaps. An LSTM adds a cell state updated by gated addition. When the forget gate stays near one, the signal travels along it almost unchanged, so the network can learn dependencies across tens or hundreds of steps. The gates are learned, so it decides what to keep.

    “Can the model see a pattern that spans three months of transactions?”

    Only if its architecture reaches that far. A 1-D conv stack sees exactly its receptive field. A recurrent model can in principle, but in practice its memory fades after tens to hundreds of steps. Often the better answer is to give it summaries: monthly aggregates as features, with the sequence model covering the recent detail. I'd test with a pattern planted at different distances to see where it stops being found.

    “Is the OCR model reliable on Arabic?”

    Not automatically. Arabic is right-to-left, letters change shape by position, diacritics are small and many fields mix Arabic and English digits. Benchmarks are often Latin-only. I'd measure character error rate separately for Arabic, English and mixed fields, by capture channel, on our own documents, and route low-confidence reads to a human.

    “A vendor says their deep model gives 99% accuracy on document classification. Convinced?”

    Not until I know the sample. I'd ask what documents, from which channels, how the test set was split, and what the do-nothing baseline scores. Then I'd run it on a held-out batch of our own scans, including poor ones, and look at the errors by class and by script rather than a single average.

    Part 7

    Self-check

    Try each one before opening the answer. The numeric ones need only the formulas in Part 2.

    1. A 64×64 greyscale image goes through a 5×5 filter with no padding and stride 1. What is the output size, and how many weights does the filter have?

    Output side = (64 + 0 − 5) ÷ 1 + 1 = 60, so 60×60. The filter has 25 weights (plus one bias), reused at all 3,600 positions.

    2. A convolutional layer takes 8 input channels and produces 32, with 3×3 filters. How many parameters, including biases?

    3 × 3 × 8 × 32 = 2,304 weights, plus 32 biases, so 2,336. It does not depend on the image size.

    3. You stack six 3×3 convolutions with stride 1. How many input pixels can one output unit see? What if the filters are dilated 1, 2, 4, 8, 16, 32?

    Plain: 1 + 6 × 2 = 13. Dilated doubling: 1 + 2 × (1 + 2 + 4 + 8 + 16 + 32) = 1 + 2 × 63 = 127. Same parameters, ten times the reach.

    4. The recurrent factor in a plain RNN averages 0.7 per step. Roughly how much signal reaches 20 steps back? And with a gated cell whose forget gate is 0.98?

    0.720 ≈ 0.0008, so about 0.08% of the signal. Gated: 0.9820 ≈ 0.67, about two thirds. That is the whole argument for gating.

    5. A fraud team's 1-D conv model uses symmetric padding and scores brilliantly offline. What is likely wrong?

    Symmetric ("same") padding with centred filters lets each output depend on later events as well as earlier ones, so the model sees the future, including the fraudulent transaction itself. Use causal padding (left only) and re-test.

    6. Why can a convolutional network find a stamp anywhere on a cheque with a few hundred labelled examples, when a fully connected one would need far more?

    The convolution ties one stamp detector across all positions, so every example teaches it at every location, and its parameter count is tiny. The fully connected model must learn the stamp separately at each position it might appear, with millions of free weights, so it needs examples of each.

    7. When would you choose a GRU or TCN over a transformer for transaction data?

    Short histories (tens to a few hundred events), a strict latency or memory budget at scoring time, modest training data, and a need to keep a small per-customer state. And as always, only if it beats a boosted-tree baseline on aggregate features under a customer-grouped, forward-in-time split.
