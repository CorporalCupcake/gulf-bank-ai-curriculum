    Synthetic Data, Model Collapse and Model Merging

    Part 1

    What these ideas are

    In one sentenceSynthetic data is training text written by a model instead of a person; model collapse is what happens when models learn from each other's output for too long; model merging is blending the weights of two trained models into one, with no new training.

    All three answer the same question: how do you get a capable model without paying the full price? Our running example is a model that writes customer complaints, to train a complaint-routing system.

    Think of photocopying a photocopy. Each copy loses a little of whatever was faint. A model trained on its own output loses the rare things first.

    How it differs from other ideas

    • Synthetic data vs real data: real data comes from people and events. Synthetic data is generated, so it can only repeat what some model already believes.
    • Collapse vs ordinary overfitting: overfitting is memorising a fixed training set. Collapse is a loop: output becomes the next input, and the spread of the data shrinks each round.
    • Merging vs ensembling: an ensemble runs several models and combines their answers. Merging combines their weights into one model, so it costs no more to run.
    Part 2

    Synthetic data and collapse

    Teams use synthetic data because good real text is finite, some data barely exists (rare cases, long reasoning chains), and a strong model is a cheap, patient writer.

    How collapse happens

    1. Train a model on real complaints.
    2. Generate a new set of complaints from it.
    3. Sample, not copy: a small sample rarely contains the rare types, so some are missing from the new set.
    4. Train the next model on that set. It has never seen the missing types, so it never writes them.
    5. Repeat. A type that is gone stays gone. Each round the data is a little narrower.

    Early on, the average looks fine and headline scores barely move, while the rare cases (the odd customer, the minority class) quietly vanish. Late on, the output becomes narrow and repetitive.

    How to read it, and how to avoid it

    • Replace vs accumulate: if each model trains only on the last output, error grows. If you keep the real data and add each synthetic batch, error stays bounded. Real web data piles up in this second way, so the internet is not collapsing overnight.
    • Keep real data in the mix. A steady stream pins the rare cases, as the slider shows.
    • Add a verifier. Unit tests, answer keys or a schema check let only good samples through. A verifier is new information the loop was missing.

    A synthetic test set is a trap: it shares the generator's blind spots, so it flatters the model. Always test on real data.

    Part 3

    Model merging

    Say you fine-tune one base model on Arabic banking text and another copy on code, and want one model that does both. Merging combines their weights in minutes, on a CPU, with no data and no training.

    The key idea is a task vector: what fine-tuning changed, meaning the fine-tuned weights minus the base weights.

    How it works

    1. Start from one shared base and make each fine-tune from it.
    2. Compute each task vector.
    3. Add them to the base, each scaled by a strength you choose (0.5 is a plain average, 1 adds the full change).
    4. Test the merge on every skill, then adjust the strength.

    How to read it

    • Why it works: fine-tunes move only a short way from the base, so the straight line between them stays in a good region.
    • Interference: if two tasks change different weights they barely clash. If they push the same weights, they pull against each other like two people on one rope, and a smaller strength is the compromise.
    • Different bases give garbage. Merging only works for fine-tunes of the same base.
    • Fancier methods exist: TIES keeps only each vector's largest changes and resolves sign clashes; DARE randomly drops 90% or more of each vector and rescales. Plain averaging or task arithmetic is a baseline they don't reliably beat.
    Show the formula

    Merged weights = base + λ₁ × (task vector 1) + λ₂ × (task vector 2). Each λ is a strength. With two models and λ = 0.5 each, this is the plain average of the two fine-tunes.

    Part 4

    Which to use

    OptionPick it whenAvoid when
    Synthetic data with a verifierOutputs can be checked (code, maths, schema-bound extraction), or real data is scarceNothing can check the output, or it would replace all real data
    More real labelled dataYou can afford to collect it and quality matters mostThe cases are rare or the data is too sensitive to share
    Distillation from a stronger modelYou want a small, cheap model that copies a larger oneLicence terms forbid it, or the teacher is wrong in your domain
    Model mergingFine-tunes share one base and you need a quick blend to testDifferent bases, heavy overlap, or you cannot re-evaluate
    • Strong at: filling gaps real data cannot, checkable domains like code, and combining skills in minutes.
    • Weak at: closed loops with no real data, evaluation, and facts nobody can verify.

    In banking, synthetic data fills thin classes in fraud and anti-money-laundering work and makes test records without customer data, but it must never be the only evidence that a model works. A merged model is a new model for governance, and its safety is not the average of its parents'.

    Part 5

    Common mistakes and quick check

    • Closed-loop training

      No fresh real data and no filter. Scores look fine for several rounds while rare cases disappear. Ask what share of the mix is real, and measure rare-case performance, not just the average.

    • Synthetic test sets

      A test set written by the generator shares its blind spots. Use a real, independent test set.

    • Merging without re-testing

      A skill can silently drop, safety behaviour can dilute, and a parent's backdoor can survive. Evaluate every parent skill plus safety.

    1. Which cases vanish first when models train on each other's output?

    The rare ones (the tails). A small sample seldom contains them, and once missing they never return, while the average still looks fine.

    2. Why does a little fresh real data help so much?

    It re-introduces the rare cases every round, so they cannot disappear for good.

    3. What is a task vector?

    The change fine-tuning made: fine-tuned weights minus base weights. Adding scaled task vectors to the base adds skills.

    4. Can you merge a model fine-tuned from base A with one from base B?

    No. Without a shared base the weights are not lined up and the result is garbage.
