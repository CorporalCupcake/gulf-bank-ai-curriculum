    Tokens and the Transformer: How an LLM Reads and Writes

    Part 1

    What an LLM does

    In one sentenceA large language model (LLM) cuts text into pieces called tokens, then repeatedly predicts the next token until the answer is complete.

    It works like phone autocomplete, only vastly bigger. Everything it seems to "know" comes from predicting a plausible next piece. We will follow one short prompt, "The bank froze the account", through the whole loop.

    How it differs from other models

    • A classifier (such as a fraud model) reads fixed columns and outputs one label. An LLM reads a sequence of any length and outputs text, one piece at a time.
    • A search engine looks up documents that already exist. An LLM generates new text from patterns it learned in training.
    • Older sequence models read words one after another. A transformer lets every token look at every earlier token at once, which is faster to train and handles long-range links better.
    Part 2

    Tokens: the pieces a model reads

    In one sentenceA token is a chunk of text, often a whole short word or part of a long one, taken from a fixed catalogue of about 100,000 to 250,000 pieces called the vocabulary.

    The model never sees letters or words. A tokeniser chops the text into catalogue pieces and swaps each for its id number. Think of Lego: the model builds with bricks, not clay.

    How the catalogue is built. Most LLMs use byte-pair encoding (BPE). Start from single characters, then repeatedly merge the most frequent neighbouring pair into a new piece, until the vocabulary reaches its target size. Nothing is "understood": it is frequency counting. Text that was common in the sample gets long pieces, and rare text stays in small ones.

    How to read token counts

    • A rough English guide is about 1.3 tokens per word. Treat it as a guide, not a rule.
    • You pay per token. The context window (how much text the model can hold at once) is also measured in tokens, and speed depends on them.
    • Language matters. English was common in tokeniser training data. Arabic, especially dialect, was less so, so the same message often needs noticeably more tokens. Reported gaps are several-fold between some languages (Ahia et al., 2023; Petrov et al., 2023). A pilot that costs a few thousand dirhams a month in English can cost far more in Arabic with no change in the model.
    • Always compare tokens for the same message, not per word, since one Arabic word can carry what takes four in English.

    What tokens explain. Asked to count the r's in "strawberry", a model receives a few token ids, not ten letters. It is like counting letters on a single Scrabble tile. Long numbers are chopped into inconsistent chunks, so never let a model do arithmetic that matters in its head. "Account", " account" and "ACCOUNT" are different tokens, so spacing and case can change behaviour.

    Part 3

    The transformer: how tokens read each other

    In one sentenceA transformer is a stack of layers in which each token looks at the earlier tokens, picks the relevant ones and blends in their information. That looking step is called attention.
    1. Look up a vector. Each token id becomes a list of numbers (an embedding) from a learned table. Tokens used in similar ways end up with similar vectors. Position information is added separately, because attention alone ignores order.
    2. Attend. Each token asks "what do I need?" (a query), compares that with what every other token offers (its key), and turns the match scores into weights that sum to one. Its new vector is the weighted blend of the others' contents (their values).
    3. Process. A small feed-forward network then works on each position on its own. Much of the model's stored knowledge sits here.
    4. Repeat. Each part adds to the running vector rather than replacing it, so each layer is a small edit. Real models stack about 24 to 100 layers.
    • Why it matters: the vector for "bank" starts the same in "river bank" and "bank account". Attention is where context changes it.
    • Many heads. Several attentions run side by side, each tracking a different relation, such as a verb's subject.
    • Causal mask. A text generator may only look at earlier tokens. Otherwise it could read the answer it is meant to predict.
    • Cost. Every token is compared with every other, so work grows with the square of the length. That is why long context is expensive.
    Part 4

    Writing: from scores to the next token

    The last vector is turned into one probability for every token in the vocabulary. For "The customer's card was ...", it might give "blocked" 40%, "declined" 30%, "lost" 20%, and a long tail of unlikely words sharing the rest. The model picks one, adds it to the text, and runs again.

    The sampling dials

    • Temperature sharpens or flattens those probabilities, like a contrast control. Low values favour the top token, and near 0 it always picks the top one. High values give unlikely tokens a real chance. It is not "creativity" and it does not make answers more accurate.
    • Top-k keeps only the k most likely tokens.
    • Top-p keeps the smallest set of tokens whose probabilities add up to p.

    Even at temperature 0, hosted models are not always identical from run to run. For regulated work, record the model version and settings, and test for stability.

    Show the loop in code

    The generation loop in plain steps (real systems add a cache so earlier positions are not recomputed):

    ids = tokenizer.encode(prompt), then repeat: logits = model(ids)[-1] gives scores for the next token, probs = softmax(logits / temperature) turns them into probabilities, nxt = sample(probs) picks one, and ids.append(nxt) feeds it back in. Stop at the end-of-text token, then tokenizer.decode(ids) gives text.

    Part 5

    Which fix for which oddity

    SymptomCauseWhat to do
    Arabic costs moreMore tokens for the same messageCount tokens on real documents with each candidate model's tokeniser
    Wrong letter or digit countsModel sees tokens, not charactersUse code or a calculator tool
    Loses the middle of a long documentAttention cost and limits grow with lengthShorten the input, retrieve only what is relevant
    Answers vary between runsSampling, even at low temperaturePin the model version, log settings, test stability
    • Strong at: fluent text, summarising, rewriting, and spotting patterns in language.
    • Weak at: exact characters, arithmetic, and guaranteeing facts. A fluent answer is not evidence of a correct one.

    In banking, check token counts for Arabic and English before you build a business case, and keep exact checks such as IBAN length or currency sums in code rather than in the model.

    Part 6

    Common mistakes and quick check

    • Costing Arabic with English ratios

      A budget based on 0.75 English words per token can be wrong by a factor of two. Measure real documents with the real tokeniser.

    • Sizing in characters

      A 2,000-character chunk can overflow a model's token limit in Arabic and be silently cut. Log token counts and re-measure after any model change.

    • Guardrails that see different text

      A keyword filter can miss look-alike characters or odd spacing that the model reads perfectly. Test with Unicode variants.

    • Treating temperature 0 as deterministic

      Run the same input many times and pin the model version.

    1. What is a token?

    A chunk of text from the model's fixed vocabulary, swapped for an id number before the model reads it.

    2. A vendor quotes the same price per token for English and Arabic. Is Arabic the same cost?

    No. The same message usually needs more Arabic tokens. Count tokens on real translated documents to estimate it.

    3. What does attention do?

    It lets each token weigh the earlier tokens and blend in the relevant ones, so "bank" can take its meaning from "account".

    4. Why can a model miscount the letters in a word?

    It sees token ids, not individual letters. Use code for exact character work.

    5. What does raising the temperature do?

    It flattens the probabilities so unlikely tokens are picked more often. It makes output more varied, not more accurate.
