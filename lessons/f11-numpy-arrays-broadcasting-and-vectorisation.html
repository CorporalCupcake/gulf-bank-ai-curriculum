    NumPy and pandas: Thinking in Arrays and Tables

    Why array operations beat loops, how broadcasting decides what can be combined, and the pandas traps that give a plausible wrong answer.

    Contents

    The whole lesson in one sentenceNumPy is fast because the loop runs in compiled code; pandas adds labels, so check row counts, indexes and dtypes after every step.

    Part 1

    The intuition

    A clerk converting a million slips from dollars to dirhams handles each slip in turn. A machine multiplies the whole stack at once. The clerk is a Python for loop; the machine is a NumPy array operation. That is vectorisation.

    pandas adds labels to arrays. That helps, but three things then happen without any error: columns are added by label, not position; joins multiply rows when a key repeats; and assigning to a slice may not change the original. Each gives a wrong number.

    Part 2

    How it really works

    What an array actually is

    A Python list is a shelf of separate boxes; a NumPy array is one tray of identical items. It has a dtype (the type of every element) and a shape (size per axis).

    A slice is a view of the same memory, so writing to it changes the original; a boolean mask gives a copy. Memory is rows × columns × bytes. Floats are inexact, so keep exact money as integer fils.

    Why a loop is slow and an array operation is not

    Python checks the type of every element and builds a new object each pass. NumPy pays a small fixed cost, then runs compiled code over the whole block. Tiny arrays gain nothing; a million rows gain fifty-fold or more.

    To vectorise, replace the loop with the operation it computes: ufuncs apply an operation to every element, boolean masks replace if, and reductions replace running totals. A for loop over DataFrame rows almost always has a much faster one-line version.

    Broadcasting: how arrays of different shapes combine

    NumPy lines shapes up from the right. On each axis the sizes must be equal or one must be 1, and a size-1 axis is stretched to fit. So monthly means of shape (12,) subtract cleanly from a (1000, 12) table.

    A failure raises an error, which is the good outcome. The danger is a shape that broadcasts when you did not mean it, such as a vector against a square table. Print .shape at each step.

    pandas in one picture: arrays with labels

    A DataFrame is a dictionary of columns, aligned by row label, each with its own dtype. Select with a condition for rows, .loc for labels and .iloc for position.

    Chained assignment such as df[mask]["flag"] = 1 changes a temporary copy, so the original is untouched. Write df.loc[mask, "flag"] = 1 in one step.

    Index alignment: the silent matcher

    For a - b, pandas matches rows by index label, like matching exam scores to students by name rather than seat. Labels with no partner give NaN. That is honest, but it is a trap when the indexes are not what you think, or when you use .values and bypass alignment, pairing the wrong rows silently.

    Filling a missing fee with 0 is plausible; filling a missing balance with 0 usually is not.

    Grouping: split, apply, combine

    groupby is SQL's GROUP BY. Aggregate returns one row per group; transform returns the original length with each group's statistic repeated on every row.

    Rows with a missing group key are dropped by default, and sum and mean skip NaN, which hides missing data.

    Joining: how rows multiply

    merge is SQL's JOIN. If a key appears twice on one side, every match on the other side doubles, and so does every total afterwards. An inner join silently drops unmatched rows, which are rarely random.

    Defences: pass validate="m:1", compare row counts and an additive total before and after, and use indicator=True to count unmatched rows. Read identifiers with dtype=str.

    Reshaping: wide, long, and the dtype checks that go with them

    Long data has one row per customer per month; wide has a column per month. Pivoting leaves NaN where a month is missing, and whether that means 0 or unknown is a modelling decision.

    After loading a file, check df.dtypes and df.isna().sum(). Dates stored as text sort alphabetically (see F11.3).

    Part 3

    How it fails, and how to spot it

    • Row-by-row loops on a DataFrame

      Using iterrows or apply(axis=1) over millions of rows runs slowly, and someone concludes Python is too slow.

      Spot itSearch for iterrows and ask what whole-column expression would do the same.
    • Silent index alignment

      NaNs appear, or values attach to the wrong customers after a sort or filter.

      Spot itCheck isna().sum() after every combination.
    • Join row explosion, or inner joins that drop rows

      A key that should be unique is not, so rows and totals inflate. Or an inner join drops the interesting unmatched rows.

      Spot itCompare rows and a total before and after, and use validate and indicator.
    • Chained assignment and accidental views

      An assignment changes nothing, or a NumPy slice edited in place changes the original data.

      Spot itUse .loc in one step and .copy() when you intend to modify.
    • Wrong axis, or dtypes left to defaults

      Standardising rows instead of columns; integers turned into floats; IDs that lost leading zeros.

      Spot itPrint shapes, test on a tiny array, and check df.dtypes after loading.
    Part 4

    Self-check

    1. balances is (1000, 12) and the means are (1000,). Why does subtracting fail, and what is the fix?

    Shapes line up from the right, so 12 meets 1000. Make the means a column with [:, None] or keepdims=True.

    2. 50 million rows of 40 float64 columns will not fit on your laptop. What can you do?

    That is about 16 GB. Use smaller dtypes such as float32 or category, or load fewer rows and columns.

    3. A thousand transactions are joined to a customer table where fifty customers appear twice. What happens, and what would catch it?

    Those customers' transactions are matched twice, inflating rows and totals with no error. validate="m:1" or a before-and-after total would catch it.

    4. Series a has index {1, 2, 3} and b has {2, 3, 4}. What does a + b give?

    Index {1, 2, 3, 4}, with NaN at 1 and 4 and sums at 2 and 3. Using fill_value=0 removes the NaN, but only sensible if missing really means zero.

    5. What is the difference between agg and transform in a groupby?

    agg returns one row per group. transform keeps the original length, repeating each group's value, which suits a transaction's share of its customer's total.
