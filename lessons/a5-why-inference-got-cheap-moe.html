    Why Inference Got Cheap: MoE, Speculative Decoding and Caching

    Part 1

    Why prices fell

    In one sentenceInference (running a trained model to get answers) got cheap because several tricks read fewer weights, get more tokens per read, or skip repeated work, and the savings stacked.

    Picture a bank assistant answering 200,000 questions a day. Every call carries the same 6,000-word instruction block. Paying full price each time is like refuelling from empty before every taxi trip.

    The key fact: generating text is memory-bound. For each token (a word or word piece) the chip reads every active weight from memory and does little arithmetic with it, like a chef who spends the shift walking to the pantry. So anything that reads fewer weights, gets more tokens per read, or avoids repeat work cuts cost.

    The five levers

    TrickWhat it avoidsChanges the answer?
    Mixture of expertsUsing most weights per tokenIt is a different model
    Speculative decodingOne big-model pass per tokenNo
    Prompt cachingRe-reading a repeated startNo
    RoutingBig model on an easy questionYes, measure it
    RetrievalReading the whole library per callYes, measure it

    Sort by the last column. Speculative decoding and caching are free lunches. Routing, smaller experts and retrieval trade some quality for money, so they need evaluation.

    Part 2

    How each trick works

    Mixture of experts (MoE)

    A normal ("dense") model sends every token past every weight. An MoE has many parallel "expert" blocks and a small router that sends each token to only the best few, like a triage nurse sending each patient to the right specialists.

    Two numbers matter. Total parameters is what you must store in memory. Active parameters is what each token uses, and sets the compute. "600 billion total, 35 billion active" stores like a huge model and computes like a mid-sized one.

    • Memory does not shrink. All experts must sit in fast memory, so hosting cost follows the total.
    • Quality sits between a dense model of the active size and one of the total size.
    • Experts are not subject specialists. They split on token patterns, not "banking" or "French".

    Speculative decoding

    Checking is cheaper than writing. A teacher marks a whole page in one pass, though the pupil wrote it word by word. Here a small draft model guesses the next few tokens. The big model checks them all in one pass, keeps those it agrees with, and corrects the first it does not.

    The big model's check means the output follows exactly what it would have written alone. It is a speed trick, not a quality trade. A poor draft wastes time, never accuracy. Templated letters speed up a lot, creative text much less.

    Prompt caching

    The KV cache is the model's notes on what it has already read. If a new prompt starts with exactly the same tokens as a recent one, the server reuses the notes and processes only the new end. It is a bookmark: you resume rather than re-read.

    1. Put stable text first: system prompt, policies, examples.
    2. Put varying text last: the customer's question.
    3. Never put a timestamp or user name at the top. One changed token at the front breaks the whole match.

    Providers charge a fraction of the normal input price for cache reads, and caches expire after minutes to hours.

    Routing

    Big models cost many times more than small ones, and most questions are easy. A router picks the model. A cascade always tries the cheap model first and escalates if its answer looks unreliable. A pre-router (a small classifier) picks before answering. Rules are the simplest: balance enquiries go small, credit memos go big.

    Long context or retrieval

    Stuffing a whole document into every prompt means paying to read it every call. Retrieval searches an index and sends only the best few passages. A 400-page policy is about 200,000 tokens, against roughly 3,500 for retrieval, so stuffing costs far more per question even with caching.

    Part 3

    How to read the claims

    "600 billion parameters, 35 billion active." Compute is that of a 35 billion model. Memory needed is that of a 600 billion model. Ask for both numbers.
    "2.4x faster with speculative decoding." Fine, and the answers are unchanged. It depends on how often the draft is right, which you must measure on your own traffic.
    "60% of questions handled by the cheap model." The cheap model still runs on every question, and the escalated 40% pay both prices. The cost saving is real. The quality of the accepted 60% is the unknown.
    "Cache hit rate 0%." Something near the top of the prompt changes every call. Check the cache-hit field in the usage output.
    Part 4

    Which to use

    TrickStrong atWeak at
    MoECheap compute at scale, high trafficLarge memory, little gain for one user
    Speculative decodingFast replies for one user, no quality lossLess benefit on a saturated server
    Prompt cachingLong repeated instructionsBreaks if the start changes
    RoutingLarge savings when most questions are easyNeeds a good easy-versus-hard signal
    RetrievalBig, changing libraries with citationsA missed passage is never seen

    Start with caching (free) and rules-based routing, then add the others as traffic grows. Always pair a cost number with a quality number.

    In banking, route by risk as well as difficulty: a cheap model should never be the only author of an adverse decision that reaches a customer. Ask your provider how tenants are isolated before putting customer data in cached prompts.

    Part 5

    Common mistakes and quick check

    • Judging an MoE by one number

      "600 billion, so as good as a 600 billion dense model", or "35 billion active, so cheap to host". Quality sits between the two, and hosting follows the total.

    • Breaking the cache by accident

      A timestamp or user name near the top makes every call a miss. Move variable text to the end.

    • A router that sends hard cases to the cheap model

      Self-reported confidence is often overconfident. Measure accuracy of accepted answers by category, including rare ones.

    • Stuffing everything into the prompt

      It costs more, runs slower and can show a user documents they should not see. Compare it with retrieval on your own questions.

    1. Which number drives compute per token for an MoE, and which drives memory?

    Active parameters drive compute. Total parameters drive memory, because every expert must be loaded.

    2. Speculative decoding uses a draft model that is often wrong. What happens to speed and to answers?

    Speed drops, because most drafts are rejected. The answers do not change, because the big model checks every token.

    3. Why does speculative decoding not change outputs, while a cascade does?

    In speculative decoding the big model checks every token. In a cascade an accepted cheap answer is final, so a different model wrote it.

    4. A prompt starts "Today is 6 November 2026, 14:03:22" and cache hits are zero. Why, and what is the fix?

    Caching needs an identical start, and the time changes every second. Move it after the stable policy text.

    5. A cascade accepts 60% of questions at AED 2 per 1,000, and the big model costs AED 30. Why is the cost not 40% of AED 30?

    The cheap model runs on every question, and the escalated 40% also pay the big price: about AED 14 per 1,000 in total.
