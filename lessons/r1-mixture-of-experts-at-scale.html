    Mixture-of-Experts and Recurrent Challengers

    Part 1

    What a mixture-of-experts model is

    In one sentenceA mixture-of-experts (MoE) model is a network made of many small specialist blocks plus a router that picks just a few of them for each token, so only a small slice of the model does work at any moment.

    Running example: an operations floor with 256 specialists (sanctions, trade finance, card disputes). A triage clerk hands each case to the eight best-placed people. The floor knows a lot, yet any one case uses a small part of it.

    How it differs from a normal model

    • Dense model: every token passes through every parameter. Cost per token rises with model size.
    • MoE model: every token passes through only the chosen experts. DeepSeek-V3 has 671 billion parameters in total but about 37 billion active per token.
    • The catch: the next token might need any expert, so all 671 billion must sit in fast memory. MoE trades memory for compute.
    Part 2

    How it works and how to read it

    1. Swap the feed-forward block. In a transformer layer, the feed-forward network holds most of the parameters. An MoE replaces it with many small copies, the experts.
    2. Score the experts. The router, one small linear layer, gives each expert a score for the current token.
    3. Keep the top few. Typically the top 2 to 8 are chosen. The others do not run at all.
    4. Blend their answers. The chosen experts' outputs are mixed, weighted by their scores.
    5. Balance the load in training. Without care, a few experts win early, get all the practice and the rest starve. DeepSeek-V3 nudges a bias on each expert's score: down if overloaded, up if idle.

    How to read the numbers

    • "Qwen-30B-A3B" means 30 billion total, 3 billion active ("A" is active). Total sets the memory you need. Active sets the arithmetic per token.
    • Neither number is "the real size". Quality tends to sit between what an active-sized and a total-sized dense model would give. Compare on your own task.
    • Many small experts beat a few big ones. Mixtral used 8 large experts and picked 2 (28 possible pairs). Newer models use 256 and pick 8, so each token gets a finer mix. Some experts are shared: always on, holding common knowledge so the others can specialise.
    • Experts are not neat topics. They tend to specialise by token type or syntax. There is no "sanctions expert".

    Why cheap per token is not always cheap to run

    Serving is mostly reading weights from memory. One token touches about 3% of 256 experts, but 64 tokens together touch nearly 90%. So the saving only appears when thousands of users share a batch. A bank hosting one model for a few hundred staff often pays the full memory bill without the speed benefit.

    Part 3

    The recurrent challengers

    In one sentenceA state-space model (SSM) reads text one token at a time and keeps only a fixed-size running summary, so memory does not grow as the text gets longer.
    • Strong at: very long inputs. Decoding costs the same at token 100 or token 1,000,000.
    • Weak at: exact lookup ("what was the second clause's penalty rate?"). A compressed summary loses detail that attention can fetch directly.
    • Mamba (Gu and Dao, 2023) made the update selective: what to keep or forget depends on the current token, so it can skip filler and keep a sanctioned name.
    • Hybrids are the practical answer: mostly SSM layers with a few attention layers for lookup. Jamba (AI21) uses roughly one attention layer per seven or eight Mamba layers, plus MoE. Nemotron-H (NVIDIA) is mostly Mamba-2. Falcon-H1 (TII, Abu Dhabi) runs attention and SSM side by side in each block, from 0.5B to 34B parameters with up to 256K context, openly licensed.
    Part 4

    Which to use

    OptionStrong atWeak at
    Large MoEQuality per unit of compute; many users at once; training efficiencyFew users, tight memory, heavy fine-tuning
    Dense modelSimple serving, easy tuning, modest private trafficFrontier knowledge at low cost per token
    Small dense, distilled or quantisedOne narrow task, edge or single-GPU hostingOpen-ended reasoning over varied inputs
    SSM or hybridVery long inputs, many long sessions, limited GPU memoryExact recall, unless tested
    Full attentionContexts under about 32K tokens where recall mattersHundreds of thousands of tokens per user

    Usable today? MoE is in production at scale: most frontier models and many open ones use it, so you probably already rely on one through an API. Hybrids are newer but shipping in open models. Self-host an MoE only if concurrency is high enough to fill big batches, and size memory from the total parameters at your chosen precision (8-bit or 4-bit).

    In banking, staff assistants and document summarisers often run on hosted MoE models unnoticed, and hybrids suit long credit files, contracts and call transcripts, provided you test retrieval on your own documents first.

    Part 5

    Common mistakes and quick check

    • "671B but only 37B, so it fits on a small machine"

      Compute is small, memory is not. All experts must be loaded. Ask for the footprint in GB at your precision.

    • Assuming cheap API prices mean cheap self-hosting

      Prices reflect huge shared batches. A lightly used private deployment leaves GPUs idle.

    • Believing "infinite context" claims for SSMs

      A fixed summary cannot store everything. Test exact lookups from the middle of your own long documents.

    • Compressing or fine-tuning without re-testing

      Aggressive quantisation or full fine-tuning can disturb routing. Re-run your own evaluation afterwards.

    1. A model is called "Model-80B-A6B". Which number sets compute and which sets memory?

    6B active sets the arithmetic per token. 80B total sets the memory you must hold.

    2. Why does load balancing matter?

    Without it a few experts hog the tokens and the rest starve. The busiest expert also sets the speed of the whole step.

    3. Why are SSMs weaker than attention at exact recall, and how do hybrids cope?

    An SSM squeezes the past into a fixed-size summary, so details can be lost. Hybrids keep a few attention layers for lookup.

    4. Thirty analysts need a private assistant. Large MoE or mid-sized dense model?

    Dense. With 30 users the batches are tiny, so the MoE's compute saving goes unused while its memory bill covers every expert.

    5. You must answer questions over 500,000-token case files. Which design?

    A hybrid, with retrieval checks. Full attention's memory per user is huge at that length, and a pure SSM may lose exact details.
