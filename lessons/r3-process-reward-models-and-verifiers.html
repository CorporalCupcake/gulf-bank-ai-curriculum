    Verifiers and Test-Time Scaling

    Part 1

    What it is

    In one sentenceTest-time scaling means spending extra computing effort while the model answers (more attempts, or more thinking), and a verifier is whatever decides which attempt is good.

    Running example: a model is asked "what is 17 × 24?" and gets it right only 3 times in 10. Checking an answer is easy (a calculator does it in a blink), while producing one is the hard part. So we let the model try many times and let a checker pick the winner.

    How it differs from other ways to improve a model

    • Bigger or retrained model: costs a lot once, then helps every question. Test-time scaling costs a little on every question, and needs no training.
    • One longer prompt: improves the instructions. Test-time scaling improves how many chances the model gets.
    Part 2

    How it works

    There are four common recipes. All rest on the same idea: spend compute, then select.

    1. Best-of-N. Draw N independent answers, score each with a verifier, and return the highest score.
    2. Majority vote (also called self-consistency, Wang et al., 2022). With no verifier, return the answer that appears most often. Right answers tend to agree, while mistakes scatter.
    3. Think longer. One attempt, but with a bigger thinking budget. In budget forcing (the s1 paper, Muennighoff et al., 2025) the model is stopped, or told to keep going by appending "Wait", so it rereads and corrects itself.
    4. Check each step, not only the end. An outcome reward model grades just the final answer. A process reward model (PRM) grades every line of working, so the first wrong step is found and bad branches can be dropped early.

    What counts as a verifier?

    • Exact check: a calculator, a unit test, or running SQL and comparing the row count. It cannot be talked round, but it only checks what it was built to check.
    • Learned judge: a model that scores answers. It is flexible, but fluent, confident wrong answers can score well.
    • Human review: accurate but slow, and easily swayed by a confident tone.

    Where an exact check exists you can even train on it, rewarding 1 for pass and 0 for fail. DeepSeek-R1 (2025) used rule-based rewards like this. It is a main reason reasoning models improved fastest on maths and code.

    Part 3

    How to read it

    Rule of thumbThe model sets the ceiling, and the verifier decides how much of it you reach. If the model is almost never right, no verifier helps.
    Model right 30% of the time, exact checker, N = 16
    At least one of 16 tries is right about 99.7% of the time, and the checker finds it. That is the best case.
    Same model, learned judge, N = 1,000
    Among a thousand answers, a few confident wrong ones almost surely outscore the right ones, because you searched for the top score. Accuracy can fall below what N = 16 gave.
    Vote where the most common answer is wrong
    If 25% of samples say 398 and 20% say 408, more votes make 398 win reliably. Voting amplifies the model's most popular answer, right or wrong.
    Split votes or low verifier scores
    A free warning sign. Send those cases to a human.

    Thinking longer has the same shape: more helps until it flattens, and models can overthink easy questions. Snell et al. (2024) found that a small model with extra compute could beat one about 14 times larger on easy and medium questions, but not on the hardest ones. Match the effort to the difficulty.

    Part 4

    Which to use, and when it breaks

    OptionUse it whenAvoid when
    Exact check + best-of-NThe answer can be recomputed or testedThe check covers only part of what matters
    Majority voteShort answers, no verifier, right answer is the usual oneFree text, or a common systematic error
    Learned verifier + best-of-NJudgement tasks, with labelled cases to measure itLarge N, or no labels to test it
    Longer thinkingHard multi-step problems, one passEasy questions, strict latency
    Bigger or fine-tuned modelHigh volume on one stable taskTask changes often, little data

    Strong at:

    • Tasks with an exact check. A handful of samples plus a checker turns a 30% model into a near-certain one.
    • Middle-difficulty questions. Easy ones do not need extra attempts, and impossible ones do not repay them.

    Weak at:

    • No reliable judge. For advice or tone, extra samples just give more fluent text.
    • Cost and delay. 32 samples cost 32 times as much, and a chat reply cannot wait.
    Show the formula

    Chance at least one of N tries is right = 1 − (1 − a)N, where a is the chance one try is right. With a = 0.3 and N = 16: 1 − 0.716 ≈ 0.997. It assumes the tries are independent and a perfect verifier.

    In banking, start with the cheapest option that works: recompute figures such as a debt-service ratio in code, and use learned judges only for the parts with no calculator.

    Part 5

    Common mistakes and quick check

    • Trusting a learned judge at huge N

      The more you search, the more likely you find its blind spot. Cap N where measured accuracy stops rising.

    • Voting on a systematic error

      If the model misreads the question the same way each time, every sample repeats it and the vote locks it in.

    • Expecting samples to fix a weak model

      If one try is almost never right, no selector helps. Fix the model, retrieval or prompt.

    • Thinking longer is always better

      Easy questions can get worse with overthinking. Set the budget by difficulty.

    Why is checking easier than producing?

    Verifying 408 = 17 × 24 is one multiplication, while writing a correct solution needs every step right. Test-time scaling exploits that gap.

    What is the difference between an outcome and a process reward model?

    An outcome model grades only the final answer. A process model grades each step, so it finds where the working went wrong.

    When does majority vote fail?

    When the most common single answer is wrong. More samples then make the wrong answer win more reliably.

    Why does best-of-N with a learned judge peak and then fall?

    Selecting the top score among many finds the confident wrong answers that fool the judge. This is reward-model over-optimisation (Gao et al., 2023).

    When is an exact check not enough?

    When it covers only part of the requirement. A correct figure in a badly reasoned memo still passes the check.
