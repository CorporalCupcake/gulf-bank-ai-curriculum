    Tuning Models Without Fooling Yourself: Search Strategies and the Classic Algorithms

    Contents
    Part 1

    The intuition

    Hyperparameters are settings the data cannot teach a model, such as tree depth or learning rate. You pick them by trying values and watching a validation score.

    Two ideas matter. First, spread your trials: a few knobs decide most of the result. Second, the best of many scores is flattering, because you selected on luck as well as quality.

    Hold onto thisExplore the knobs that matter, and keep a test set nothing touched.
    Part 2

    How it really works

    Grid versus random search

    Think of tuning a radio: one dial changes the station and the others barely matter. Validation error usually moves a lot along one or two knobs and hardly at all along the rest, and which knobs matter changes from dataset to dataset (Bergstra and Bengio, 2012). A learning rate that is too high ruins a boosted model; minimum leaf size shifts the score by a fraction of a point. Researchers call this low effective dimension.

    A grid tests only a few distinct values of the knob that matters, because it spends its budget on combinations. With 25 trials over three knobs you get about three values of each. Random search draws every knob independently, so every trial is a new value of the important one. You can also stop at any time or add trials later, which a grid cannot do without starting again.

    A grid is fine for one or two knobs. Beyond that, go random. Sample scale-type knobs such as learning rate and regularisation strength on a log scale, because their effect depends on order of magnitude. Set ranges from knowledge, so no trials go to absurd settings.

    Bayesian search and early stopping

    When trials are costly, learn from earlier ones. Bayesian optimisation fits a cheap surrogate model to the scores so far, then tries the next setting where the predicted error is low or the surrogate is unsure. That balance of exploiting and exploring is scored by expected improvement, the orange curve below. Tools like Optuna do this for you. It pays off when each trial is expensive and the knobs are few.

    Where the important knob's landscape is flat, grid and random tie. Where it is sharp, as learning rates often are, random wins clearly at small budgets. If a trial takes an hour, though, neither is a good way to spend 50 hours.

    Bayesian search is not magic. It needs a sensible search space, and on noisy scores it can chase noise. The surrogate also gets harder to fit as knobs multiply. For a model that trains in a minute, 200 random trials may beat a careful 30. In practice you use TPE (the default in Optuna and Hyperopt) or SMAC, which cope with mixed and conditional knobs, such as "kernel width only matters if the kernel is RBF".

    The second lever is not finishing bad trials. Like auditioning many singers and hearing only the best in full, successive halving gives many settings a small budget, keeps the best half and repeats with more budget. Boosting libraries also build in early stopping: stop adding trees once validation error stops improving, so the tree count becomes an outcome, not a knob. Set a high tree cap, a low learning rate, and let early stopping choose.

    Tuning on the test set

    Twenty students of equal ability sit a 100-question quiz, and whoever tops the class got lucky. In the same way, suppose twenty models all truly get 80% of questions right. Scored on 100 test questions, they scatter by about 4 points through sampling noise, and the best of twenty reads around 87%. That is the number you would report, and it is wrong. This selection effect is the winner's curse. Use three sets, each for one job:

    • Training data fits the parameters.
    • Validation data (or cross-validation folds) chooses hyperparameters, so its best score is optimistic.
    • Test data is touched once, at the end. If you look, change something and look again, it has become validation data.

    With little data, use nested cross-validation: an inner loop runs the search, and an outer loop scores the whole procedure on folds the search never saw. It is costly, so it suits small data, not nightly jobs. For anything that moves in time, the outer split must run forward in time, not shuffle.

    Optimism depends on evaluation noise compared with real differences between candidates. If candidates differ by a point and noise is four points, tuning 200 settings finds noise. So cap trials in advance and log every trial so the search can be audited. Then apply the one-standard-error rule: choose the simplest model whose score is within one standard error of the best. A simpler model has fewer ways to have won by luck.

    k-NN, SVMs and naive Bayes

    These older algorithms still turn up in interviews and in production, as baselines or components. Each is a clear assumption about the world, and knowing the assumption tells you where it fails.

    AlgorithmCore idea and assumptionWhere it still wins
    k-nearest neighboursVote among the k most similar training cases; no training step. Assumes nearby points share labels.Small data; look-alike lookups; vector search.
    Support vector machineFind the widest-margin boundary between classes; only points near it matter. Assumes a wide margin generalises.Small to medium data with many features, such as text.
    Naive BayesAdd up evidence per feature. Assumes features are independent given the class, which is almost never true.Text baselines and tiny training sets.

    k-NN: scale first. k-NN needs scaled features, or a salary in the thousands swamps age in years and the model quietly becomes "nearest by salary". Then comes the curse of dimensionality: with hundreds of raw features, nearest and farthest neighbours end up almost equally far, like finding a "close" restaurant that must match 300 criteria. It works best on a few features or a learned embedding, which is what vector search does. It is also slow at prediction time, because every query compares against the stored data unless you use an index.

    SVM: the widest road. An SVM picks the widest road between two groups of houses. C sets how many points may sit on the wrong side, and a kernel (a recipe for curving the boundary) has its own width, γ; a large γ overfits. Tune C and γ together on a log scale. Training cost grows quickly with rows, so beyond about a hundred thousand rows boosted trees or a linear model take over. SVM scores are not probabilities.

    Naive Bayes: count the evidence. For a message, it tallies how typical each word is for each class and picks the class with the most evidence. It ranks well, but features like "transfer" and "urgent" co-occur, so it counts the same evidence twice and its probabilities come out too extreme. Use it as a first baseline, not as a source of probabilities. Logistic regression wins with enough data, naive Bayes with very little.

    Here k is the bias-variance dial: k = 1 is high variance, huge k is high bias. Do scaling inside a pipeline fitted on training folds only, or information from the validation data leaks into training.

    Strengths, limits and when to use it

    Strong at

    • Random search covers important knobs cheaply. Every trial is a fresh value of every knob, so it needs no assumptions about which knob matters and parallelises perfectly.
    • Bayesian search saves expensive trials. The surrogate turns each past result into a guess about where to look next, so a 2-hour model can be tuned in 30 trials, not 300.
    • A held-out test set gives an honest number. Because it never influenced a choice, its score has no selection bias, and that is what a risk committee needs.
    • k-NN, SVMs and naive Bayes need little data and little tuning. Their assumptions act as strong priors, so they are hard to overfit with a few hundred rows. k-NN also needs no training, and naive Bayes trains in one pass.

    Weak at, or don't use when

    • Grids over many knobs. The cost explodes while the important knob still gets few values.
    • Bayesian search on cheap or very noisy trials. The surrogate has little signal and overhead dominates; plain random search wins.
    • Any search when candidates differ by less than the noise. More trials only raise the winner's optimism.
    • k-NN on many raw features or millions of rows. Distances lose meaning and prediction is slow.
    • SVMs on large data, or where you need probabilities. Training is superlinear in rows and the scores need calibrating. Naive Bayes is weak when features overlap heavily and you need probabilities.

    Alternatives and how to choose

    OptionPick it whenAvoid when
    Grid searchOne or two knobs, cheap model, want a full picture.Three or more knobs.
    Random searchDefault for most work; trials are parallel and fairly cheap.Each trial costs hours and budget is tiny.
    Bayesian (TPE, GP)Expensive trials, a moderate number of knobs, fairly clean scores.Very noisy scores, dozens of knobs, or trials under a minute.
    Successive halving / early stoppingTraining can be cut short and partial results predict final ones.Early scores mislead, as with slow-starting models.
    k-NN / SVM / naive BayesSmall data, text, or a quick baseline.Large tabular data: use gradient boosting; need calibrated probabilities: use logistic regression.

    In practice. Start with defaults and early stopping, then run 50 to 100 random trials on the three or four knobs that matter, scored on forward-in-time folds. For boosted trees those are usually learning rate, depth, minimum leaf size and subsampling. Move to Optuna if each trial is expensive. Freeze the choice, then score the test set once. Compute is rarely the limit: the hours go into the data, not the search.

    In banking this is the routine step between a baseline and a model that goes to validation. A fraud model is tuned on earlier months and scored on a later month. Credit scorecards often keep a simpler setting because model risk teams value stability over a fraction of a point. Naive Bayes and k-NN appear in complaint triage and in look-alike customer or document search.

    Part 3

    How it fails, and how to spot it

    • Tuning on the test set

      The test number becomes a validation number and is optimistic.

      Spot itAsk how often the test set was scored.
    • Quoting the best validation score as performance

      The search's best score is reported as the live result.

      Spot itAsk for the score on a separate, later period.
    • Grid search over many knobs

      Five values on six knobs is 15,625 runs, and still only five learning rates.

      Spot itCount the grid.
    • Leaky preprocessing

      A scaler fitted before cross-validation, or shuffled folds on time-ordered data, rewards the leak.

      Spot itLook for a pipeline and a forward-in-time splitter.
    • Chasing differences smaller than the noise

      Two hundred trials to move AUC from 0.912 to 0.914.

      Spot itCompare the gain with the fold-to-fold spread. Inside it, stop and pick the simpler model.
    • Unscaled features

      Pay in thousands drowns out age in years in k-NN or an SVM, so the model ignores most of your features.

      Spot itPrint feature ranges and check that scaling sits inside the pipeline.
    • Trusting scores as probabilities

      A naive Bayes 0.99 is not a 99% chance, and SVM margins are not probabilities at all.

      Spot itPlot a calibration curve on held-out data before using scores as risk estimates.
    Part 4

    Self-check

    1. Why does random search explore the important knob better than a grid?

    A grid spends its budget on combinations, so few distinct values of each knob get tried. Random search tries a new value of every knob each time.

    2. Why sample the learning rate on a log scale?

    Its effect depends on order of magnitude, and a uniform draw puts most trials at the high end.

    3. Twenty identical models are scored on 100 test questions. Why does the best look better, and is it?

    Sampling noise scatters the scores, and the maximum of twenty sits above the true value. It is no better; you selected on luck.

    4. What is the difference between validation and test data in tuning?

    Validation data is used repeatedly, so its best score is optimistic. Test data is used once, after the choices are frozen.

    5. You feed age (years) and monthly pay (dollars) unscaled into k-NN. What goes wrong?

    Pay dominates the distance, so age is effectively ignored. Standardise inside a pipeline.

    6. Each training run takes 4 hours and you have a week on one GPU. Which search would you choose and why?

    Bayesian search with early stopping or successive halving. With about 40 trials possible, a surrogate that learns from each one and stops bad runs early beats random draws. Random search would be fine only if you had many parallel machines.

    7. You have 800 labelled complaints and need a first classifier by tomorrow. Naive Bayes, an SVM or gradient boosting: which would you choose and why?

    Naive Bayes or a linear SVM on word counts. Both train in seconds, cope with many sparse features and few rows, and give a baseline to beat. Boosting needs more data, and you would not trust naive Bayes probabilities, so use it only for ranking.
