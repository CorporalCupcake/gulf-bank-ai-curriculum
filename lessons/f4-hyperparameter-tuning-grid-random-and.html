    Other Classic Models and Tuning Them

    Part 1

    Three older models

    In one sentencek-nearest neighbours, support vector machines and naive Bayes are three older ways to classify things, each built on one simple assumption about the world.

    Our running example: predict whether a house is expensive or cheap from its size (across) and how close it is to the city centre (up). Here are two of the three at work.

    How each one works

    • k-nearest neighbours (kNN): there is no training. To predict a new house, find the k most similar houses (say 3) and take a vote. Assumption: similar houses sell for similar prices.
    • Support vector machine (SVM): draw the dividing line with the widest empty road between the two groups. Only the houses on the edge of the road (circled) matter. Assumption: a wide road will still separate new houses.
    • Naive Bayes: look at each feature on its own, ask "how much more common is this among expensive houses than cheap ones?", and add up the evidence. Assumption: features are independent, which is almost never true, so it is "naive". It still works surprisingly well on text, such as spam filtering, where each word is one piece of evidence.

    How they differ from other models

    • Versus logistic regression: that also draws one line, but fits it by weighing every house. An SVM cares only about the ones near the line.
    • Versus trees: trees cut the space into boxes with yes/no questions. kNN needs no rules at all; it just looks up neighbours.
    • Versus gradient boosting: these three are simpler and rarely win on tables of data, but they are quick baselines and still useful in a few niches (see Part 3).
    Part 2

    Tuning: finding good settings

    In one sentenceA hyperparameter is a setting you choose before training, such as k in kNN or tree depth, and tuning means trying values and keeping the one that scores best on held-out data.

    The model learns its own numbers from the data. It cannot learn its hyperparameters, so you search for them. There are three common ways.

    1. Grid search: list a few values for each setting and try every combination. Fine for one or two settings.
    2. Random search: pick each setting at random within sensible ranges and try, say, 30 combinations. Usually better beyond two settings.
    3. Bayesian search: after each trial, a cheap helper model guesses where the next good setting is and tries there. Tools like Optuna do this. It pays off when each trial takes a long time.

    The picture shows why random search wins. Usually one or two settings matter a lot and the rest hardly matter. A grid wastes trials repeating the same few values of the important one. Random search tries a fresh value every time. Search scale-type settings (learning rate, regularisation strength) on a log scale: 0.001, 0.01, 0.1, not 0.1, 0.2, 0.3.

    The trap: the best score is flattering

    Imagine 20 students of equal ability sitting a quiz. Whoever tops the class got lucky. Tune enough settings and the same happens to your models: the winner's score is partly luck, so it is too good to be true. Keep three separate sets, each with one job.

    Cap the number of trials in advance, and write down every trial. If two settings score within noise of each other, pick the simpler one. With little data, use cross-validation for the validation step (next lesson).

    Boosting libraries also offer early stopping: stop adding trees once validation error stops improving, so the number of trees stops being a setting you search.

    Part 3

    How to read them, and which to use

    • kNN's k: k = 1 copies the single nearest house, so it is jumpy and overfits. A large k smooths everything towards the overall average. Try values like 5, 15 and 50 and let validation choose.
    • SVM's margin setting (called C): a high C insists on classifying every training house correctly and risks overfitting. A low C allows a few mistakes for a wider road.
    • Scale first: kNN and SVM both measure distances. If size is in square feet (up to thousands) and distance in km (up to 20), size swamps everything. Rescale features to similar ranges.

    In practice: start with logistic regression or gradient boosting. Reach for kNN when "similar to this one" is the question, an SVM for medium-sized, wide data, and naive Bayes when you need a fast text baseline.

    Show the formula

    Naive Bayes score for "expensive" = how common expensive houses are overall × (how common feature 1 is among expensive houses) × (how common feature 2 is among expensive houses) × … Do the same for "cheap" and pick the higher score. Multiplying the features separately is exactly the independence assumption.

    In banking, these models mostly appear as quick baselines and as components, such as nearest-neighbour lookup for similar transactions or naive Bayes for filtering text, while tuned gradient boosting does the main scoring.

    Part 4

    Common mistakes and quick check

    • Forgetting to scale for kNN and SVM

      A feature with large numbers silently dominates the distance. Rescale first.

    • Tuning on the test set

      Every peek turns it into validation data and your final score becomes optimistic. Touch it once.

    • Using a grid with many settings

      The budget gets spread thin over repeated values. Use random search.

    • Reporting the best of many trials as the expected score

      The winner is partly lucky. Report the score from fresh data.

    1. What is a hyperparameter, and how does it differ from a parameter?

    A hyperparameter is a setting you choose before training (such as k or tree depth). Parameters are the numbers the model learns from the data.

    2. Why does random search usually beat grid search?

    Only a few settings matter. A grid repeats the same few values of them, while random search tries a new value of each setting every trial.

    3. A kNN model with k = 1 gets 100% on training data and does badly on new data. What do you change?

    Raise k. With k = 1 it copies single neighbours, which overfits. Pick k by validation score.

    4. Twenty tuned models all score about 80% on validation, and the best shows 84%. Should you expect 84% in production?

    No. The best score is partly luck. Expect nearer 80%, and check on an untouched test set.

    5. Why is naive Bayes called "naive"?

    It treats every feature as independent evidence, which is rarely true. It often still ranks well, but its probabilities are over-confident.
