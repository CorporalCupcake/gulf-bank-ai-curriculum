    Superposition and Sparse Autoencoders

    Part 1

    What superposition is

    In one sentenceSuperposition is a model storing more concepts than it has neurons, by giving each concept its own direction and letting the directions overlap a little. A sparse autoencoder (SAE) is a tool that unpacks those directions so people can read them.

    Take a tiny model layer with 4 neurons. You might expect it to hold 4 ideas, one per neuron. In practice it holds far more, such as "cat", "fraud", "Dallas" and "sad", because at any moment only a few of them are in use.

    The result is messy. One neuron fires for several unrelated things (a polysemantic neuron), so a single neuron is not a unit of meaning. The unit of meaning is the direction: a particular mix of neurons.

    How it differs from what you might expect

    • One neuron, one idea (the tidy picture). Sometimes true, but not the rule. Superposition is why looking at single neurons is incomplete.
    • A linear probe. A probe looks for one concept you chose. An SAE has no labels and finds concepts nobody asked about.
    Part 2

    How a sparse autoencoder works

    An SAE is a small extra network trained on one layer's activations. It rebuilds each one from a short list of features.

    1. Collect activations. Run text through the model and save the numbers from one layer, over hundreds of millions of tokens.
    2. Encode. A wide layer, often 8 to hundreds of times bigger than the input, turns each activation into a code with one entry per candidate feature.
    3. Force it to be sparse. A penalty on the size of the code pushes most entries to exactly zero, so only a handful of features stay on.
    4. Decode. The decoder adds up the directions of the active features to rebuild the original activation.
    5. Read the features. Look at the text where each fires most and name it.

    Sparsity is what makes this work. Because few concepts are on at once, the leakage between overlapping directions stays small, and the SAE can pull them apart again. If many concepts were on together, the leakage would add up and the packing would fail.

    Transcoders and attribution graphs. An SAE reads one snapshot. A transcoder instead predicts a layer's output from its input through sparse features, so you can see how one feature leads to the next. Linking features across a whole prompt gives an attribution graph: a wiring diagram for one prompt and one answer. Anthropic's circuit-tracing work (Ameisen et al., 2025) builds these.

    For "the capital of the state containing Dallas is", Dallas feeds Texas, which feeds Austin.

    Part 3

    How to read the results

    Reconstruction error high
    The SAE rebuilds the activation badly. What it misses still affects the model, so any story from its features is partial. Swapping the SAE into a language model usually raises the model's loss noticeably.
    A "Golden Gate Bridge" feature
    In Claude 3 Sonnet, turning it up made the model bring up the bridge in unrelated answers (Templeton et al., 2024). That is the strongest evidence a label is right.
    Error nodes in an attribution graph
    These hold the part of the computation the graph cannot explain. If most influence flows through them, the graph explains little. Check this first.

    How much to trust a feature label

    Weakest: a human can name what it fires on. Better: the label predicts where it fires on new text. Strongest: turning it up or down changes behaviour as expected.

    Known problems: the penalty makes features look weaker than they are (shrinkage); a bigger SAE splits "city" into "Gulf cities" and "Texan cities", so no size is the right one; and retraining can give different features.

    Part 4

    Which to use, and when

    ToolUse it whenAvoid when
    SAE, transcoder, attribution graphExploring unknown features or mechanisms in an open-weight model you controlYou need a firm answer now, or only have API access
    Linear probeYou have labels for a known concept and want a detectorYou want to discover concepts
    Activation patchingTesting whether a layer or direction matters causallyYou want names for what is inside
    Behavioural tests, red-teamingJudging what the model does, as risk sign-off needsYou want to know why it does it
    SHAP or reason codesTabular credit, fraud or AML modelsThe model is a language model

    Strong at:

    • Readable units. Sparsity turns tangled neurons into directions you can inspect.
    • A causal handle. A feature is a direction, so you can add or remove it and see what happens.

    Weak at: complete accounts (the unexplained remainder is large), stable feature lists (they shift with seed and size), coverage (one graph covers one prompt) and closed models (you need the weights).

    Is it usable today? This is research, not production tooling. Do not build a control around it. Anthropic published its circuit-tracing library in May 2025 for open-weight models such as Gemma-2-2B and Llama-3.2-1B, so a team can learn the methods on a small model.

    Show the numbers behind superposition

    A layer with d dimensions has only d exactly perpendicular directions, but random directions are nearly perpendicular: the typical overlap of two is about 1 ÷ √d, or about 3% at d = 1,000.

    In banking, the nearest use is inspecting an in-house open-weight assistant for features tied to sensitive topics. It is not a source of customer-facing decision reasons.

    Part 5

    Common mistakes and quick check

    • Taking a feature's name as its meaning

      The label came from the top examples. Elsewhere the feature may fire on something else. Ask how it was checked on random activations.

    • Ignoring the unexplained remainder

      A poor SAE or a high error-node share makes any feature story partial. Ask for the loss with the SAE spliced in.

    • Cherry-picked graphs

      One beautiful prompt says nothing about how many failed. Ask how many prompts were tried.

    • Mistaking correlation for use

      A feature can fire on fraud-related text while behaviour does not depend on it. No intervention, no causal claim.

    1. Why does sparsity make superposition possible?

    When few concepts are on at once, the leakage between overlapping directions is small, so each can still be read back.

    2. What does raising an SAE's sparsity penalty do, and what do you lose?

    Each input is explained by fewer, cleaner features. You lose reconstruction accuracy, and feature strengths shrink.

    3. How is a transcoder different from an SAE?

    An SAE rebuilds its own input. A transcoder predicts a layer's output through sparse features, so you can trace one feature's effect on the next.

    4. A graph shows Dallas to Texas to Austin. What shows the Texas step is really used?

    An intervention on the real model: suppress Texas and Austin should weaken, or swap in California and it should say Sacramento. A tidy graph alone is only a story.

    5. A regulator asks why a boosted-tree model declined a loan. SAE or reason codes?

    Reason codes from methods such as SHAP. SAEs are for language models and give partial, hypothesis-grade evidence.
