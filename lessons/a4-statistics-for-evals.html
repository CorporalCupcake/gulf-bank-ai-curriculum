    Statistics for Evals

    Part 1

    Why an eval score needs an error bar

    In one sentenceAn eval score is an estimate from a sample of questions, so it wobbles: a different set of questions would give a slightly different score, even with the model unchanged.

    A team tests a credit-policy assistant on 100 questions. Version 1 gets 82 right, version 2 gets 85. The slide says "+3 points" and a manager asks to ship. But the 100 questions are only a sample of everything customers might ask. A fresh 100 could give 79 and 84, or 86 and 83.

    This is the standard error and confidence interval idea from F2: a score is a percentage, so it gets an interval.

    At 100 questions the range around a score near 85% is roughly 7 points either way. A 3-point gap is lost inside it.

    How it differs from ordinary testing

    • Software tests pass or fail, and rerunning gives the same answer. An eval score is an average over a sample, so it is a statistic.
    • The grader adds its own noise. Free-text answers can't be matched by string, so another LLM often grades them, with its own biases (Part 4).
    Part 2

    How to read an eval score

    85% on 100 questions
    The believable range is about 77% to 91%. Not 85% exactly.
    85% on 400 questions
    Four times the questions halves the range, to roughly 81% to 88%.
    82% versus 85%, same 100 questions
    Cannot be told apart. Do not ship on this alone.

    How to get an honest number

    1. Count the cases. The range shrinks only with the square root of the number of cases.
    2. Use the right interval. The simple "score ± 2 SEs" rule breaks near 0% and 100% (it can pass 100%). Use the Wilson interval for percentages. For other metrics, use the bootstrap.
    3. Check the cases are really independent. Ten paraphrases of each of 50 scenarios are not 500 independent questions. The honest sample size is closer to 50 (Miller, 2024, recommends clustered standard errors).
    4. Remember model randomness. At a non-zero temperature the same question gets different answers. Rerunning does not replace more questions.
    Part 3

    Comparing two versions

    In one sentenceBoth versions answered the same questions, so compare them question by question and look only at where they disagree.

    Don't check whether two separate intervals overlap. Easy questions are easy for both models and hard ones are hard for both, so that difficulty cancels out when you pair the results.

    A paired test (McNemar's test) or a paired bootstrap uses exactly this. Similar models rarely disagree, so pairing is much sharper than comparing two scores.

    How many questions do you need?

    • Paired: to detect a 3-point gain when the models disagree on 10% of questions, about 870 questions.
    • Separate question sets: roughly 2,600 per model for the same gain.
    • Smaller gains cost far more. Halving the gain you want to detect roughly quadruples the questions.

    Size the test set before you build it. If you can't afford the questions, say now that the test can't resolve the gain you care about.

    Part 4

    When an LLM grades the answers

    In one sentenceAn LLM judge is a cheap, fast grader with predictable habits, so measure it against humans before trusting its pass rate.

    A strong model sees the question, the answer and a rubric, and gives a verdict. It agrees with humans about as often as humans agree with each other on open-ended chat (Zheng et al., 2023). It also has biases:

    • Position bias: favours the first (sometimes the second) answer regardless of content (Wang et al., 2023). Swapping the order can flip the winner.
    • Length bias: longer answers score higher even when the extra adds nothing (Dubois et al., 2024).
    • Self-preference: rates text from its own model family higher (Panickssery et al., 2024).
    • Style over substance: confident tone raises scores, and fluent wrong answers can pass. Judges may be less reliable in Arabic, so measure it.

    Average both orders to cancel position bias. Length and self-preference don't depend on order, so they need length-matched comparisons or a judge from a different family. Where a check can be run (execute the SQL), run it instead of asking a judge.

    Calibrate the judge

    Hand-grade a sample of answers, then measure two rates, as for any classifier.

    • Sensitivity: the share of truly good answers the judge passes.
    • Specificity: the share of truly bad answers it fails.

    Think of a smoke alarm. At 80% specificity, one bad answer in five slips through as a pass, so the raw pass rate is inflated. A judge that passes 78% with 92% sensitivity and 80% specificity implies a true pass rate of about 81%. If the two rates add up to barely over 100%, the judge is close to a coin flip and no correction helps.

    The two rates come from a small human-graded set, so the corrected score has two sources of uncertainty. An interval that ignores the calibration set is overconfident (Lee et al., ICML 2026).

    Part 5

    Which tool to use

    QuestionUseWhy
    How precise is one score?Wilson intervalSafe for percentages near 0% or 100%
    Interval for any other metric?BootstrapResample questions and watch the score move
    Is version 2 really better?Paired test or paired bootstrapCancels question difficulty
    Is the judge trustworthy?Human-graded sampleGives sensitivity and specificity to correct the pass rate
    • Strong at: stopping decisions based on noise, and sizing a test before spending on it.
    • Weak at: bias. A bigger test set shrinks luck but not a biased judge or unrepresentative questions.
    Show the formula

    Corrected pass rate = (observed pass rate − (1 − specificity)) ÷ (sensitivity + specificity − 1). With 78%, 92% and 80%: (0.78 − 0.20) ÷ 0.72 ≈ 0.81. The bottom line is close to 0 for a coin-flip judge, which is why the correction fails there.

    In banking, a policy assistant should not go live on a "+3 points" slide: report the paired difference with an interval, from a judge that has been checked against human reviewers.

    Part 6

    Common mistakes and quick check

    • Reporting a score with no interval

      On a few hundred questions most "improvements" sit inside the noise.

    • Comparing two intervals instead of pairing

      Use the same questions and test the per-question differences. Separate intervals throw away information.

    • Counting paraphrases as independent

      500 questions from 50 scenarios behave like far fewer than 500.

    • Picking the best of many prompts

      The winner of 20 tries is inflated by luck. Confirm it on fresh questions, and don't keep adding questions until a result looks significant.

    1. Version 2 scores 85% and version 1 scores 82% on the same 100 questions. Ship?

    Not on this evidence. The ranges overlap heavily. Run a paired test on the disagreements.

    2. How do you halve the error bar on a score?

    Use four times as many independent questions.

    3. Which questions carry information in a paired comparison?

    Only those where the two versions disagree.

    4. Averaging both answer orders fixes which judge bias?

    Position bias only. Length bias and self-preference remain.

    5. Why can a judge with 80% specificity not be taken at its word?

    One bad answer in five slips through as a pass, which inflates the raw pass rate. Correct it using both rates.
