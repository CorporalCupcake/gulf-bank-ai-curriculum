    Neural Networks from the Inside: Neurons, Backpropagation and Trainable Depth

    What a network actually computes, how one clean rule (the chain rule) trains millions of weights, and why depth only works because of three tricks: careful initialisation, normalisation and skip connections.

    Contents

    The whole lesson in one sentenceA neural network is a stack of weighted sums and bends that learns by measuring, for every weight, how much the error would change if it moved (backpropagation), and very deep stacks train only because initialisation, normalisation and residual connections keep that signal from vanishing or exploding on its way back.

    Part 1

    The intuition

    Think of a fraud analyst judging a card payment. She weighs several small signals at once: high amount for this customer, 3 a.m., new merchant, unfamiliar device. Each nudges her suspicion up or down by a different amount. If the total passes a level, she pauses the payment.

    That is one neuron: a weighted sum of inputs plus a bias, passed through a bend. A layer is many such analysts, each weighting the same inputs differently, so each spots a different pattern. The next layer sees their verdicts ("looks like card testing", "looks like travel"), not raw transactions. Stack layers and the network builds features nobody wrote down.

    Learning works like tuning dials by feel. Start with random weights, show a transaction and the truth, and measure the error. Backpropagation asks every weight: "if I nudged you up a little, would the error rise or fall, and by how much?" Every weight then takes a small step that reduces the error. Repeat millions of times.

    Depth adds a problem. That "how much would the error change" message travels backwards through every layer and is multiplied at each one. It is like whispering down a line of 100 people: if each repeats it slightly quieter it vanishes, slightly louder and it blows up. Much of deep learning's engineering since 2010 is about keeping that message alive.

    Hold onto this(1) A neuron is a weighted sum plus a non-linear bend; without the bend, stacking layers adds nothing. (2) Backpropagation is the chain rule applied efficiently: one backward sweep gives the gradient for every weight. (3) Depth is a signal-propagation problem; initialisation, normalisation and skip connections are the three fixes.
    Part 2

    How it really works

    One neuron: a weighted vote and a bend

    A neuron multiplies each input x by a weight, adds a bias, and applies an activation function f:

    z=w1x1+w2x2+ba=f(z)

    Weights say how much each input matters and in which direction. The bias sets how easily the neuron fires. z is the plain linear score; a is what is passed on. A sigmoid f alone gives exactly logistic regression (F4.2): a network is that core, repeated and stacked.

    Geometrically, z = 0 is a straight line (a plane in higher dimensions). The neuron answers one question: which side of the line is this input on, and how far? The weights set the line's direction (the dot product from F1.1). Move the sliders and watch it.

    The slope in the third box matters later, because backpropagation multiplies by it at every neuron. Sigmoid is steepest at the centre (slope 0.25) and flat at both ends (near 0), which is the root of the "vanishing gradient". ReLU has slope exactly 1 on its active side and 0 on the other, so it largely replaced sigmoid inside deep nets. Transformers mostly use smooth ReLU relatives (GELU, SiLU).

    Tanh(ez − e−z) / (ez + e−z)−1 to 1Recurrent cells; small tabular nets.
    ReLUmax(0, z)0 to ∞Default for feed-forward and convolutional nets.
    GELU, SiLUz · Φ(z), z · sigmoid(z)about −0.28 to ∞Inside transformer blocks, often gated (SwiGLU).

    Layers, and why the bend is not optional

    A layer of H neurons is a matrix multiplication plus the bend: a = f(Wx + b). A network chains these. A fraud scorer with 40 inputs, 64 hidden units and 1 output has 40×64 + 64 + 64×1 + 1 = 2,689 parameters. Language models are the same arithmetic with billions.

    The bend is essential. With f as the identity, two layers give W2(W1x), which is one matrix W2W1. It is like stacking transparent sheets that are all straight rulers: you still only get a straight line. A hundred linear layers collapse into one, which cannot beat logistic regression.

    The universal approximation theorem (Cybenko 1989; Hornik 1989) says one wide-enough hidden layer can approximate any reasonable continuous function. It says such a network exists, not that gradient descent finds it, that it is small, or that it generalises. In practice depth buys efficiency: some functions need exponentially many neurons in one layer but few in a stack, because later layers reuse earlier features.

    The classic test is XOR: label 1 when the two inputs have the same sign. No single line separates the classes, so a single neuron (or any linear stack) tops out around 50 to 75%. Two bent neurons solve it. Simulation 2 shows this learning live.

    Backpropagation: the chain rule, run backwards

    Training needs the gradient of the loss L for every weight (F1.3 covers descent). Picture the network as a chain: input, layer 1, layer 2, ..., output, loss. The chain rule says a weight's effect on the loss is the product of local effects along the path from that weight to the loss.

    The trick is sharing work. A forward pass stores each layer's activations. One backward pass then carries δ, "how much does the loss change if this neuron's z changes?". For layer l:

    δl=(Wl+1Tδl+1)⊙f′(zl)∂L∂Wl=δlal−1T

    In words: the error signal at layer l is the next layer's signal sent back through the same weights (WT), then scaled neuron by neuron by the bend's slope f′. A layer's weight gradient is that signal times the activations that fed in: a weight matters in proportion to how active its input was and how much the downstream error cares. ⊙ means element-wise multiply.

    At the output there is a neat simplification. For a sigmoid output with cross-entropy loss (standard for fraud or default), the starting signal is just δ = p − y: predicted probability minus true label. Say 0.9 for a legitimate transaction (y = 0) and δ = 0.9, a hard push. Say 0.01 and δ = 0.01, barely a nudge. The sigmoid's slope cancels against the log, leaving a clean, never-vanishing error (F6, F1.6).

    Cost is the key engineering fact. One backward pass costs about two forward passes, whatever the number of weights. Nudging each weight and re-measuring costs one forward pass per weight: absurd at 10 billion weights. Backpropagation (Rumelhart, Hinton and Williams, 1986) made deep learning feasible.

    Frameworks (PyTorch, JAX) run the backward pass for you, but you will read training logs, so know the loop:

    for batch in loader:                 # a few hundred examples at a time
    p = model(batch.x)               # forward: compute and store activations
    loss = bce(p, batch.y)           # one number: how wrong, on average
    optimiser.zero_grad()
    loss.backward()                  # backward: fills .grad for every weight
    optimiser.step()                 # w -= lr * (a function of .grad)

    Simulation 2 runs this loop on a tiny network, no libraries. The data is XOR in two features. You choose the hidden layer's width and activation.

    Three things to notice. (1) The network is never told "same sign": each hidden unit finds one slanted line and the output neuron combines them. (2) Nothing happens for a while, then loss collapses: early weights are small and symmetric, and learning must break that symmetry. (3) The finite-difference check agrees with backpropagation to many digits. This gradient checking is how people verify a hand-written backward pass; it shows there is no mystery in the number.

    Real training uses mini-batch stochastic gradient descent: a random few hundred examples give a noisy but cheap gradient. Adam (Kingma and Ba, 2015) and AdamW, the standard optimisers, scale each weight's step by a running estimate of its gradient size, so weights with tiny gradients still move. For a transformer, batch size, learning rate, warm-up and weight decay together decide whether training works at all (F1.3).

    Initialisation: start the signal at the right size

    Small random starting weights sound harmless and are where deep nets used to fail. A layer with n inputs sums n terms, so with weight variance σ² and unit-variance inputs the output variance is about nσ². Too small and the signal shrinks layer by layer until every input gives the same output; too large and it saturates or overflows. It compounds: 0.9 per layer becomes 0.005 after 50 layers, and 1.1 becomes 117.

    The cure is to keep variance near 1 from layer to layer:

    Xavier / Glorot:Var(w)=1ninHe / Kaiming:Var(w)=2nin

    Glorot and Bengio (2010) derived Xavier for tanh and sigmoid-like activations. He et al. (2015) noted that ReLU zeros half the signal, so weights need twice the variance. For 256 inputs: Xavier std = 1/16 = 0.0625, He std = √(2/256) ≈ 0.088. Biases start at zero. Frameworks apply these by default; it matters for custom builds or when the loss will not move.

    Initialisation must also break symmetry. If all weights started equal, every hidden neuron would compute the same thing, get the same gradient and stay identical forever. Random starts let neurons specialise.

    Normalisation: re-centre the signal at every layer

    Weights change during training and the scale can drift. Normalisation layers rescale activations on the fly: subtract the mean, divide by the standard deviation, then let the network learn a scale γ and shift β to undo it if useful:

    x^=x−μσ2+εy=γx^+β

    The variants differ in what μ and σ are computed over. Batch norm (Ioffe and Szegedy, 2015): all examples in the batch, per feature. Layer norm (Ba et al., 2016): all features of one example. RMSNorm (Zhang and Sennrich, 2019): drops mean subtraction; cheaper, about as good.

    VariantStatistics overBehaviour at inferenceTypical home
    BatchNormThe batch, per featureUses stored running averages, so train and test behave differently. Awkward with small or non-i.i.d. batches.Convolutional vision models, some tabular nets
    LayerNormThe features of one exampleIdentical to training. No batch dependence.Transformers, sequence models
    RMSNormThe features of one example, no meanIdentical to training.Most recent open large language models

    Why it helps: the original "internal covariate shift" story was weak. Santurkar et al. (2018) found batch norm smooths the loss surface and makes gradients predictable, allowing larger learning rates. Practical effects: faster, more stable training, less sensitivity to initialisation, mild regularisation. In transformers, norm placement decides whether very deep stacks train without careful warm-up.

    For tabular banking models, standardise inputs (F3.4). Raw AED amounts (1 to 5,000,000) next to a binary flag train badly, and no norm layer fully rescues it.

    Residual connections: a highway for the gradient

    By 2015, even with good initialisation and normalisation, a 56-layer network trained worse than a 20-layer one on the training set. That is not overfitting; it is harder optimisation. He et al. (2016) changed each block from hl+1 = F(hl) to

    hl+1=hl+F(hl)∂hl+1∂hl=I+∂F∂hl

    The block only learns a correction to its input, like editing a draft rather than rewriting it. The derivative gains an identity I, so the gradient always has a direct path multiplied by 1, whatever F does. A zero-output block is a valid "do nothing" layer, so extra depth cannot easily hurt.

    Every transformer block is h + Attention(Norm(h)), then h + MLP(Norm(h)). The running vector h is the residual stream: each layer reads it and writes small additions back (R5 treats it as working memory).

    Side effect: each block adds to h, so its size grows with depth (with a He-scale ReLU branch, variance roughly doubles per block). The fix is pre-norm: normalise the input to each branch and leave the stream alone. Xiong et al. (2020) showed pre-norm transformers have well-behaved gradients at initialisation and need less warm-up; most large models use it.

    Simulation 3 puts all three tricks on one stage: a random deep network, one input forward, one gradient backward, computed exactly in your browser.

    Reading the picture. Sigmoid at depth 20: slope at most 0.25, so each layer shrinks the gradient and early layers receive about nothing. That is the vanishing gradient (Hochreiter, 1991; Bengio et al., 1994), which kept deep nets out of reach for twenty years. ReLU at He scale preserves size on average. Too-large weights multiply at every layer: the exploding gradient, usually seen as a loss that suddenly becomes NaN. Gradient clipping, which caps the gradient norm, is the emergency fix.

    With skips and no norm, nothing vanishes, but each block adds a full-size contribution, so forward signal and gradient grow with depth (small initial residual branches tame this). With layer norm before each block, both stay in range. This pairing is in essentially every transformer you will meet.

    Part 3

    How it fails, and how to spot it

    Most failures are quiet: training runs and produces a number. Each has a quick check.

    • Loss does not move from about 0.69 (or the base-rate value)

      The network outputs the same probability for everyone. Causes: learning rate far too small, dead activations, unscaled inputs, a bug in the labels.

      Spot itCheck that the model can overfit a batch of 50 examples to near-zero loss. If not, the pipeline is broken, not the idea. Check the average prediction against the base rate.
    • Loss turns NaN or jumps

      Exploding gradients, a learning rate too high, or log(0) in a hand-written loss.

      Spot itLog the gradient norm each step. A sudden rise precedes the spike. Gradient clipping and lower learning rate are the first fixes.
    • Dead ReLUs

      A neuron whose pre-activation is negative for every input outputs zero, gets a zero gradient and never recovers. Large learning rates cause it.

      Spot itCount the share of hidden units that are zero on a whole batch. If it is above 30–50% something is off.
    • Unscaled inputs

      AED amounts next to binary flags. The big feature dominates every weighted sum.

      Spot itLook at each input's mean and standard deviation before training. Standardise, or log-transform heavy tails.
    • Different results on every run

      Random initialisation and batch order give a different model per seed. A single run's score may be luck.

      Spot itAsk for results over five or more seeds, with the spread. Differences smaller than the seed-to-seed spread are noise.
    • Train/eval mismatch from batch norm

      Excellent training metrics, poor live ones, because batch statistics differ from the stored averages at inference, or the model was left in training mode.

      Spot itConfirm evaluation uses eval mode, and compare metrics with and without batch statistics. Layer norm avoids the issue.
    • A network where a simpler model would do

      A deep net on 3,000 labelled rows and 30 columns, claimed to beat logistic regression by a point of AUC.

      Spot itAsk for the boosted-tree and logistic baselines on the same time-ordered split, with intervals. A one-point gain on small data is usually noise.
    • Believing the universal approximation theorem means it will work

      The theorem says a good network exists, not that training finds it or that it generalises.

      Spot itWhen a pitch cites it as evidence, ask for held-out, forward-in-time results instead.
    • Treating output scores as probabilities

      A sigmoid output is not automatically calibrated. Modern deep networks tend to be overconfident (Guo et al., 2017).

      Spot itPlot a reliability curve on held-out data (F7.4) and recalibrate before using the score in a threshold or an expected-loss figure.
    Part 4

    Self-check

    Answer before opening.

    1. A sigmoid neuron has weights (2, −1), bias −0.5, and receives inputs (1.5, 0.5). What does it output?

    z = 2×1.5 − 1×0.5 − 0.5 = 2.0. The sigmoid of 2 is 1 ÷ (1 + e−2) ≈ 0.881. Its slope there is 0.881 × 0.119 ≈ 0.105.

    2. How many parameters has a network with 100 inputs, a hidden layer of 64, a second hidden layer of 32, and one output?

    (100×64 + 64) + (64×32 + 32) + (32×1 + 1) = 6,464 + 2,080 + 33 = 8,577. Each layer has a weight matrix plus one bias per output unit.

    3. Why can't ten stacked linear layers do more than one?

    The product of matrices is a single matrix. W10…W1x equals Mx for M = W10…W1. Without a non-linearity between them, the layers add no expressive power. This is why Simulation 2 stalls well short of 100% with "Linear".

    4. The output is a sigmoid with cross-entropy loss. The model says 0.9 for a transaction that is legitimate (y = 0). What is the starting error signal, and what if it had said 0.01?

    δ = p − y = 0.9 − 0 = 0.9, a strong push. At 0.01 it is 0.01, nearly none. The error signal is simply "prediction minus truth".

    5. A 20-layer network uses sigmoids, whose slope is at most 0.25. Roughly how much can the gradient shrink from the slopes alone?

    0.2520 ≈ 9 × 10−13. Weights can partly offset this, but with sizes near one the early layers receive essentially no signal. That is the vanishing gradient.

    6. A layer takes 256 inputs and uses ReLU. What weight standard deviation does He initialisation use, and why not the Xavier value?

    √(2/256) ≈ 0.088, against Xavier's 1/16 = 0.0625. ReLU zeros out about half the pre-activations, which halves the variance of the signal, so the weights need twice the variance to compensate.

    7. Why does a residual connection help the gradient, in one sentence?

    The derivative of h + F(h) is I + ∂F/∂h, so the backward signal always has a direct path multiplied by one, however poorly the block F is behaving.

    8. A colleague says "more hidden units guarantees a better model because of universal approximation". What is wrong?

    The theorem is about existence of an approximating network, not about finding it by gradient descent or about generalising to new data. More units can fit noise and need more regularisation, more positives to support them and more compute.
