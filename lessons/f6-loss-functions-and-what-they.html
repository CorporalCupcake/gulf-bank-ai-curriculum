    Loss Functions: What Training Optimises

    Part 1

    What a loss function is

    In one sentenceA loss function is a score for how wrong a prediction is. Training is just the search for weights that make the average score as low as possible.

    Running example: a bakery forecasts how many loaves it will sell each day. If the forecast says 90 and 110 sell, the miss is 20 loaves. The loss turns that miss into a single cost number.

    The model learns whatever lowers the number you gave it, not what you meant. So the loss is how you tell the model which mistakes matter most.

    How it differs from a metric

    • Loss is what training minimises. It must be smooth enough for the weights to be nudged step by step.
    • Metric is what you report to people, such as accuracy or "average miss in loaves". It can be anything that is easy to explain.
    • They are often different. Accuracy cannot be nudged smoothly (a prediction is either right or wrong), so classifiers train on a smooth loss and are judged on accuracy.
    Part 2

    How a loss steers training

    1. Predict. The model makes a forecast for each training example.
    2. Compare. The loss turns each miss into a penalty.
    3. Average. The penalties are averaged into one number.
    4. Nudge. Training works out which way to change each weight to lower that number, and moves a small step that way. (The step size is the learning rate, covered in the gradient descent lesson.)
    5. Repeat until the number stops falling.

    Every loss answers a hidden question: what number do you want? The answer depends on how the penalty grows with the size of the miss.

    Losses for predicting a number

    • Squared error (MSE) squares the miss. A miss of 20 costs 400, four times a miss of 10. It predicts the mean (the average day). One huge odd row can dominate, so use it when big values are real signal.
    • Absolute error (MAE) uses the size of the miss as it is. It predicts the median (the middle day), so odd days barely matter. Use it when outliers are noise, such as a till error.
    • Huber is squared for small misses and absolute for big ones. You get smooth training and robustness, at the cost of one setting (where "big" starts).
    • Quantile (pinball) loss charges under-prediction and over-prediction differently, so the model predicts a chosen quantile (the level the real value stays under that share of the time).

    How to read the choice

    Say nine days sell 92 to 110 loaves and a festival day sells 600. The mean jumps to about 150, while the median stays near 100. If the festival is real and the baker must bake for it, the mean carries that news. If 600 was a typing error, the median protects you. The outlier question is a business question.

    Lopsided costs work the same way. If a missed sale costs four times a wasted loaf, the best forecast is not the average. It is the 80th percentile, because you accept a shortfall about one day in five. The rule is shortfall cost ÷ (shortfall cost + waste cost): 4 ÷ (4 + 1) = 0.8. Squared error aims near the 50th percentile, which is wrong for this bakery by design.

    Train a 10th and a 90th percentile model and you get a prediction interval with no distribution assumed.

    Part 3

    Losses for yes or no answers

    In one sentenceCross-entropy (also called log loss) charges a classifier by how surprised it was by the truth, so confident wrong answers are punished very hard.

    Picture a forecaster who says "1% chance of rain" and gets soaked. For spam or not spam, the model outputs a probability. On a real spam email, a model that said 50% takes a small penalty, one that said 1% takes a big one, and one that said 0.001% takes a huge one. There is no ceiling.

    Why it is the default. With squared error on probabilities, the correcting push goes quiet exactly when the model is confidently wrong, so it barely learns. Cross-entropy pushes hardest when the model is most wrong. It is lowest when the model reports the true probability, which is why calibration checks mean something.

    • Class weights multiply the loss on rare positives. They inflate the output probabilities, so the numbers no longer mean what they say.
    • Focal loss and label smoothing help with extreme imbalance or over-confidence, but they also distort calibration. Check it.
    • Business losses weight each mistake by its cost, such as a missed fraud by the amount at stake. Powerful, but they tie the model to today's cost estimates, so document them.
    Part 4

    Which loss to use

    LossPredictsStrong atWeak at
    Squared errorThe meanSmooth, easy to trainOne huge outlier dominates
    Absolute errorThe medianIgnores odd rowsConstant slope, can train slowly
    HuberBetween the twoSmooth and robustOne extra setting to choose
    QuantileA chosen quantileLopsided costs, intervalsSeparate quantiles can cross
    Cross-entropyAn honest probabilityAny yes/no or multi-class problemVery confident errors dominate; noisy labels hurt

    In practice: numbers, start with squared error, or Huber if outliers are noise. Categories, use cross-entropy. Before training, finish the sentence "being wrong by X in this direction costs me Y". The loss is that sentence in mathematics.

    Show the formulas

    Let the miss be actual minus predicted. Squared error = miss². Absolute error = |miss|. Cross-entropy for a true answer given probability p = −ln(p). If p is 1 the loss is 0. If p is 0.5 it is about 0.69. If p is 0.01 it is about 4.6.

    In banking, a missed fraud usually costs far more than a false alert, so the loss (or the decision threshold) should reflect that asymmetry rather than treat both errors alike.

    Part 5

    Common mistakes and quick check

    • Optimising the wrong thing

      Squared error forecasts the average, even when running short is far worse than having a surplus. Match the loss to the real costs.

    • Comparing losses across models

      A loss value only means something for the same loss and the same data. Report a metric people understand as well.

    • Trusting probabilities after re-weighting

      Class weights, focal loss and label smoothing change what the output means. Recalibrate or check.

    • Blaming the model for a loss problem

      If a model "does not work", first ask whether the loss rewards what you actually want.

    1. What is the difference between a loss and a metric?

    The loss is what training minimises, so it must be smooth. The metric is what you report, and can be anything easy to explain.

    2. Which loss predicts the median, and why does that help with outliers?

    Absolute error. A median ignores how far out an odd value is, while a mean is pulled towards it.

    3. A missed sale costs three times a wasted loaf. Which quantile should you forecast?

    3 ÷ (3 + 1) = 0.75, so the 75th percentile.

    4. Why does cross-entropy beat squared error for probabilities?

    It pushes hardest when the model is confidently wrong. Squared error goes quiet there, so training stalls.

    5. You add class weights and your probabilities look too high. Why?

    The weights inflate the loss on rare positives, which inflates the predicted probabilities. Recalibrate them.
