    Attention and Embeddings: How Models Look Things Up and Where Meaning Lives

    Contents
    Part 1

    The intuition

    Attention is how a word finds the other words that matter. In "The transfer to the supplier failed, so I asked the branch to reverse it", what is "it"? Every word asks a question, every other word shows a label, and the best matches get the most weight. The transformer, built from attention, sits under almost every language model.

    Models read vectors, not words. An embedding maps an item to a vector, trained so items that behave alike land close together. "Puppy" and "dog" should be neighbours; "dog" and "spreadsheet" should not.

    Hold onto thisEmbeddings store meaning as position in space. Attention combines meaning as a weighted average. Everything else repeats these two ideas.

    Picture a shelf of six books. Each book has a key (its topic) and a value (its star rating, from 0 to 1). You walk up with a query (what you are in the mood for). Attention scores how well each topic matches your mood, turns the scores into weights that add to 100%, and returns the weighted average rating. It is a lookup that blends instead of picking one book.

    Part 2

    How it really works

    Queries, keys and values

    Think of a library. Your search words are the query, the catalogue entries are the keys, and the book you take home is the value. Every token gets all three views. Score each query against every key, turn the scores into weights that sum to 1, then take the weighted average of the values.

    The three views are not given. Each is the token's embedding multiplied by its own learned matrix, so the model learns what to ask, what to advertise and what to hand over. That split matters: what makes a token easy to find (key) can differ from what it contributes once found (value).

    A row of weights reads as "how much of my new vector comes from each other token". A high weight does not mean "this token caused the answer". Each extra point of score multiplies a weight by about 2.7, so small score gaps become clear favourites.

    A weighted average ignores order, so "bank robbed the man" and "man robbed the bank" would look identical. Transformers therefore add position information to the embeddings before the first layer.

    Why divide by √d

    Big vectors make attention all-or-nothing: scores grow with vector size, one key takes nearly all the weight, and the layer stops learning. Dividing scores by the square root of the vector size keeps them sane. It is a stability trick, nothing more.

    The link is the softmax, the step that turns scores into weights. It exaggerates gaps: when the top score is far ahead, its weight approaches 1 and the others approach 0. A nearly one-hot softmax has almost no gradient (no learning signal), so the other keys stop being trained. The same idea appears at generation time as "temperature", where a lower value gives more predictable output.

    Multi-head attention and what heads learn

    One attention pattern is not enough. Multi-head attention runs several side by side, each with its own questions, like several readers highlighting a contract for different things. Heads do recognisable jobs, but attention weights are not a reliable explanation of an answer. Never show an attention heat map to a validator as "the model's reasoning".

    The heads split the vector into slices, so the cost is about that of one wide head. A word may need its subject, a number three words back and an earlier mention of a name, all at once. One well-known job is the induction head: it sees "A B ... A" and predicts "B", which is a basis for in-context learning. Many heads turn out redundant and can be pruned.

    Each layer pairs attention, which moves information between tokens, with a feed-forward block that transforms each token alone. Much of a model's stored knowledge sits in those feed-forward blocks rather than in attention.

    Causal masks, cost, and the KV cache

    Causal mask. A model predicting the next token must not see it, so generation models let each token attend only backwards. Encoders (for embeddings and classification) let every token see every other, which suits a representation of a whole text.

    Cost. The score table quadruples when text doubles. FlashAttention computes the exact same result with far less memory traffic, which made long context affordable. The KV cache stores earlier keys and values so each new token is cheap, but it grows with every token, so memory becomes the bottleneck (see context windows and the KV cache). Sharing keys and values across heads, as grouped-query attention does, shrinks it sharply.

    Embeddings: turning things into points

    An embedding layer is a table with one row per token. Training moves the rows so tokens used alike end up close; nobody tells the model that petrol and fuel are related. Directions in the space then encode relations, as in king − man + woman ≈ queen (fragile, but the geometry is real). The number of dimensions is a design choice: 256 to 1,536 is typical for text, and 16 to 64 is usual for merchant or customer vectors. Kinds you will meet:

    KindOne vector for…Catch
    Static wordeach word, whatever the context"bank" (river) and "bank" (money) share a vector.
    Contextualeach word in its sentenceDepends on the whole input.
    Entitya merchant, customer or accountNew entities have none (cold start).

    Sentence embeddings are trained contrastively (F5.7). Multilingual ones put "dog" and "perro" (Spanish) together, because they train on translation pairs. That is what makes cross-lingual search work.

    Measuring closeness. Cosine similarity compares direction only and is the default for text. Dot product also rewards length, so use it only if the model was trained with it. Use the ruler the model was trained with; a mismatch returns wrong neighbours silently. Euclidean distance is the straight-line gap and ranks exactly as cosine does if vectors are scaled to length 1.

    Vector search. Embed the query, then return the nearest stored vectors. At scale, an approximate index trades a little recall for large speed gains. Compression is another lever: a 1,024-number vector costs about 4 KB, so ten million documents cost about 40 GB before any index.

    Entity embeddings. Instead of one-hot encoding 200,000 merchants, learn a small vector per merchant so rare ones borrow strength from similar ones, then feed the vectors to a gradient-boosted model. If learned from data that includes the test period or the label, they carry the answer (F3.1).

    A transformer repeatedly refines embeddings by letting them consult each other. The embedding table is a fixed lookup; after each attention layer a token's vector is rewritten using its neighbours.

    Strengths, limits and when to use it

    Strong at:

    • Long-range links. Any token reads any other in one step, so "it" in a long sentence finds its noun. Older recurrent models had to pass information along a chain and forgot.
    • Parallel training. All positions are processed at once on a GPU, which is why models could grow to billions of parameters.
    • Transfer. Embeddings learned on huge unlabelled text carry over to small tasks, so a few hundred labelled examples can be enough.
    • Similarity across wording and language. Search by meaning finds "reverse a payment" when the policy says "recall a transfer", and across Arabic and English.
    • Handling sparse categories. A learned merchant vector lets rare merchants borrow from similar ones, where one-hot encoding gives each its own empty column.

    Weak at, or don't use when:

    • Very long inputs. Cost grows with the square of length and the cache with length, so 300-page files need chunking, retrieval or a cheaper attention variant.
    • Small tabular data. With a few thousand rows and clean columns, gradient boosting usually beats a transformer and trains in seconds.
    • Exact facts and negation. Embeddings capture topic better than polarity or precise numbers. "Waivable" and "not waivable" sit together.
    • Explanations. Attention weights are not a faithful reason for an output, so they cannot carry a model-risk sign-off on their own.
    • Cold start and drift. A new merchant has no learned vector, and vectors trained on last year's behaviour go stale.
    OptionPick it whenAvoid when

    Recurrent networks (LSTM, GRU)Small streaming sequences on tight hardware, where a fixed memory is acceptable.Long dependencies or large-scale pretraining.

    In practice. Start with a pretrained embedding model and cosine similarity on a small labelled test set from your own data, before any fine-tuning. Try keyword search first as a baseline; a hybrid of keyword and vector search is often best. Use the dimension the model ships with, normalise vectors, and store the model version. Fine-tuning a small encoder needs hundreds to thousands of labelled pairs and a single GPU; training a transformer from scratch is rarely sensible for a bank.

    In banking, embeddings drive complaint triage, policy search and retrieval for assistants, merchant-name matching for AML screening, and entity vectors as inputs to fraud and credit models. Attention sits inside every chat assistant and document-extraction model. Where decisions need explanation, keep the transformer for text and let a simpler model make the scored decision.

    Part 3

    How it fails, and how to spot it

    • Reading attention maps as explanations

      Weights show where information flowed, not what the answer depended on.

      Spot itWas the claim tested by altering the highlighted words? If not, it is illustration only (F8).
    • Length surprises

      A prototype on five-page documents works; 300-page loan files are slow and costly, or the key facts mid-prompt are ignored.

      Spot itTime three input lengths and move the key passage around.
    • Wrong ruler or mixed models

      A dot-product index on a cosine-trained model, or queries and documents embedded by different model versions. Nothing crashes; retrieval is quietly worse.

      Spot itStore model name and version with every vector and refuse mismatches.
    • Near means similar, not true

      The closest passage to "can staff waive the fee?" may say the opposite, because negation barely moves a vector.

      Spot itPut negated and "except when" cases in the test set, and add a re-ranker.
    • Trusting a leaderboard for Arabic or domain text

      A model that tops an English average may do poorly on Gulf-dialect complaints or bilingual contracts.

      Spot itBuild 100 to 200 real query-and-passage pairs per language and measure recall at 5 for each candidate.
    • Leaks and entity-embedding traps

      Vectors of customer data are personal data, since text can often be partly rebuilt from its embedding. Entity vectors learned over the whole year leak the future into a March fraud model, and new merchants have no vector at all.

      Spot itApply the source's access controls to the vector store. Check each embedding was trained before the prediction date. Report new entities separately.
    Part 4

    Self-check

    1. A query matches three keys with scores of 2, 1 and 0. What should the weights look like, and what does "sharper" do?

    The best match gets the most weight but not all of it: about two-thirds, a quarter and a tenth. Sharper pushes towards a hard pick; blunter towards a plain average.

    2. Why are attention scores divided by √d?

    Scores grow with vector size and softmax exaggerates gaps, so one key would take nearly all the weight and learning stalls. Dividing is a stability trick.

    3. Context doubles from 8,000 to 16,000 tokens. How do the score table and the KV cache grow?

    The table grows 4 times, with the square of length. The cache grows 2 times, in proportion to length.

    4. Two vectors point the same way, but one is five times longer. How do cosine and dot product treat them?

    Cosine ignores length and calls them identical. Dot product rewards the long one. Use the measure the model was trained with.

    5. Why can retrieval return a policy that says the opposite of what the user needs?

    Embeddings capture topic far better than polarity, so "fees may be waived" and "fees may not be waived" sit nearly together. Add a re-ranker and test negated queries.

    6. You have 4,000 labelled card-fraud rows with 30 numeric columns and a request for a "transformer model". Which would you choose, and why?

    Gradient boosting. The data is small and tabular, a transformer would overfit and be harder to explain, and boosting trains in seconds. Use a learned merchant embedding as one extra input only if there is enough history per merchant.

    7. For searching 50,000 bilingual policy pages, would you pick keyword search, vector search or both, and why?

    Both. Vector search handles paraphrase and Arabic-English matches; keyword search catches exact clause numbers and product names that vectors blur. Add a re-ranker, then test on real queries per language.
