    F5.5 · F5.6 Day one ★ About 45 minutes

    Attention and Embeddings: How Models Look Things Up and Where Meaning Lives

    Attention is a soft, learned lookup that lets every word read every other word. An embedding is the vector that makes a word, a merchant or a customer something a model can compare.

    Contents

    The whole lesson in one sentenceAn embedding turns each item into a point whose position carries meaning; attention lets each item build a new, context-aware point as a weighted average of the others, weighted by how well its question matches their labels.

    Part 1

    The intuition

    Attention is how a word finds the other words that matter. In "The transfer to the supplier failed, so I asked the branch to reverse it", what is "it"? Every word asks a question, every other word shows a label, and the best matches get the most weight. The transformer, built from attention, sits under almost every language model.

    Models read vectors, not words. An embedding maps an item to a vector, trained so items that behave alike land close together. Petrol station and fuel retailer should be neighbours; an ATM withdrawal and a crypto transfer should not.

    Hold onto thisEmbeddings store meaning as position in space. Attention combines meaning as a weighted average. Everything else repeats these two ideas.
    Part 2

    How it really works

    Queries, keys and values

    Think of a library. Your search words are the query, the catalogue entries are the keys, and the book you take home is the value. Every token gets all three views. Score each query against every key, turn the scores into weights that sum to 1, then take the weighted average of the values.

    A row of weights reads as "how much of my new vector comes from each other token". A high weight does not mean "this token caused the answer".

    Why divide by √d

    Big vectors make attention all-or-nothing: scores grow with vector size, one key takes nearly all the weight, and the layer stops learning. Dividing scores by the square root of the vector size keeps them sane. It is a stability trick, nothing more.

    Multi-head attention and what heads learn

    One attention pattern is not enough. Multi-head attention runs several side by side, each with its own questions, like several readers highlighting a contract for different things. Heads do recognisable jobs, but attention weights are not a reliable explanation of an answer. Never show an attention heat map to a validator as "the model's reasoning".

    Causal masks, cost, and the KV cache

    Causal mask. A model predicting the next token must not see it, so generation models let each token attend only backwards. Encoders (for embeddings and classification) let every token see every other.

    Cost. The score table quadruples when text doubles. The KV cache stores earlier keys and values so each new token is cheap, but it grows with every token, so memory becomes the bottleneck (see context windows and the KV cache). Sharing keys and values across heads, as grouped-query attention does, shrinks it sharply.

    Embeddings: turning things into points

    An embedding layer is a table with one row per token. Training moves the rows so tokens used alike end up close; nobody tells the model that petrol and fuel are related. Directions in the space then encode relations, as in king − man + woman ≈ queen (fragile, but the geometry is real). Kinds you will meet:

    KindOne vector for…Catch
    Static wordeach word, whatever the context"bank" (river) and "bank" (Gulf Bank) share a vector.
    Contextualeach word in its sentenceDepends on the whole input.
    Entitya merchant, customer or accountNew entities have none (cold start).

    Sentence embeddings are trained contrastively (F5.7). Multilingual ones put "cash withdrawal" and "سحب نقدي" together.

    Measuring closeness. Cosine similarity compares direction only and is the default for text. Dot product also rewards length, so use it only if the model was trained with it. Use the ruler the model was trained with; a mismatch returns wrong neighbours silently.

    Entity embeddings. Instead of one-hot encoding 200,000 merchants, learn a small vector per merchant so rare ones borrow strength from similar ones. If learned from data that includes the test period or the label, they carry the answer (F3.1).

    A transformer repeatedly refines embeddings by letting them consult each other.

    Part 3

    How it fails, and how to spot it

    • Reading attention maps as explanations

      Weights show where information flowed, not what the answer depended on.

      Spot itWas the claim tested by altering the highlighted words? If not, it is illustration only (F8).
    • Length surprises

      A prototype on five-page documents works; 300-page loan files are slow and costly, or the key facts mid-prompt are ignored.

      Spot itTime three input lengths and move the key passage around.
    • Wrong ruler or mixed models

      A dot-product index on a cosine-trained model, or queries and documents embedded by different model versions. Nothing crashes; retrieval is quietly worse.

      Spot itStore model name and version with every vector and refuse mismatches.
    • Near means similar, not true

      The closest passage to "can staff waive the fee?" may say the opposite, because negation barely moves a vector. An English leaderboard winner may also do poorly on Gulf-dialect text.

      Spot itTest on real Arabic and negated cases, and add a re-ranker.
    • Leaks and entity-embedding traps

      Vectors of customer data are personal data. Entity vectors learned over the whole year leak the future into a March fraud model.

      Spot itApply the source's access controls to the vector store. Check each embedding was trained before the prediction date.
    Part 4

    Self-check

    1. A query matches three keys with scores of 2, 1 and 0. What should the weights look like, and what does "sharper" do?

    The best match gets the most weight but not all of it: about two-thirds, a quarter and a tenth. Sharper pushes towards a hard pick; blunter towards a plain average.

    2. Why are attention scores divided by √d?

    Scores grow with vector size and softmax exaggerates gaps, so one key would take nearly all the weight and learning stalls. Dividing is a stability trick.

    3. Context doubles from 8,000 to 16,000 tokens. How do the score table and the KV cache grow?

    The table grows 4 times, with the square of length. The cache grows 2 times, in proportion to length.

    4. Two vectors point the same way, but one is five times longer. How do cosine and dot product treat them?

    Cosine ignores length and calls them identical. Dot product rewards the long one. Use the measure the model was trained with.

    5. Why can retrieval return a policy that says the opposite of what the user needs?

    Embeddings capture topic far better than polarity, so "fees may be waived" and "fees may not be waived" sit nearly together. Add a re-ranker and test negated queries.
