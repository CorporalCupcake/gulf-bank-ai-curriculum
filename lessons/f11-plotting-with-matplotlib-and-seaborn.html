    From DataFrame to Honest Chart, and From Notebook to Code You Can Rerun

    How matplotlib and seaborn actually fit together, what makes a chart tell the truth, why a notebook can show results that no clean run would produce, and the small habits that make your work reproducible by someone else, including future you.

    Contents

    The whole lesson in one sentenceA chart is a claim, so choose axes, bins and encodings that make the true claim easiest to see; a notebook is a scratchpad with hidden state, so restart, run all, pin seeds and environments, and move anything reused into plain modules before anyone relies on it.

    Part 1

    The intuition

    A default is a decision someone else made, and you own the chart. Monthly card-fraud losses are AED 41.2m, 42.0m, 43.1m and 44.0m. Plot them with the y-axis starting at 40 and the last bar is over three times the first. The room hears "losses tripled". The real rise is 6.8%. The library picked a sensible-looking axis, and nobody was dishonest on purpose.

    A notebook can show a number no clean run would produce. You edit a threshold, run a later cell, delete the earlier one. The notebook remembers none of it. A week later the rerun gives a different alert count from your slide, and the state that made the slide has gone.

    Both have one root: the output is only as trustworthy as the process behind it, and the reader cannot see the process. Honest charts show results to people. Reproducible code shows them to your future self, your reviewer and the model validator.

    Hold onto thisAsk two questions of every chart: what is the one conclusion, and could someone reach a wrong one from the same picture? For notebooks ask a third: if I restart and run everything top to bottom, do I get the same numbers?
    Part 2

    How it really works

    Plotting with matplotlib and seaborn

    Matplotlib is the engine; seaborn is the driver for common routes. Matplotlib draws lines, rectangles, text and ticks. Seaborn takes a DataFrame and column names, does the grouping and statistics, then calls matplotlib. It returns matplotlib objects, so you can always adjust them. You need both.

    Matplotlib has two styles. The pyplot state machine (plt.plot(...)) tracks a hidden "current" figure: fine for a throwaway cell, confusing with several panels. The object-oriented style makes the objects explicitly. Use it for anything you keep.

    import matplotlib.pyplot as plt
import seaborn as sns

fig, ax = plt.subplots(figsize=(7, 4), layout="constrained")
sns.histplot(data=tx, x="amount_aed", hue="segment",
             log_scale=True, bins=40, element="step", ax=ax)
ax.set_xlabel("Transaction amount (AED, log scale)")
ax.set_title("Card spend by segment, March 2026")
fig.savefig("amount_by_segment.png", dpi=200)

    Three objects: a Figure is the whole canvas, an Axes is one plot area with its own scales, an Artist is anything drawn. Most "how do I change X" questions are answered by finding the Axes and calling a method on it.

    Seaborn has two layers:

    • Axes-level (histplot, scatterplot, boxplot, lineplot) draw into an Axes you pass with ax=.
    • Figure-level (displot, relplot, catplot) make their own figure and split into panels with col= and row=. Great for exploring ("one panel per segment"), awkward inside a hand-built layout.
    • seaborn.objects is a newer layered style. Recognise it; the older functions stay the everyday route.

    The loop: tidy the data (one row per observation, one column per variable), pick the chart by the question, then label. The question picks the chart:

    You want to showReach forBank example
    One distributionHistogram, or ECDFTransaction amounts, days past due
    Distributions across groupsOverlaid ECDFs, boxplots, violins; small multiplesTicket size by segment or branch
    Change over timeLine chart; few groupsWeekly alert volume, PSI by month
    Relationship of two numbersScatter; hexbin or transparency when denseUtilisation against limit
    Compare a few quantitiesBars from zero, or dots sorted by sizeFraud loss by channel
    Rate and its uncertaintyPoint with interval bars (F2.1)Recall by model with 95% interval

    Why the zero rule exists. People judge position on a shared scale far more accurately than length, angle, area or colour (Cleveland and McGill, 1984). A bar encodes value as length from a baseline, so a non-zero baseline makes the length lie: it is like a ruler whose first 40 cm are cut off. A dot or line encodes position, so a non-zero axis is fine if labelled. The lie factor is the change the picture shows divided by the real change; 1.0 is honest, and a misreading to avoid is trusting a chart because its numbers are right.

    Two more traps. Bin width in a histogram can create or hide structure (Simulation 2). Overplotting turns 200,000 scatter points into a solid blob, so density reads wrongly.

    Habits that keep charts honest:

    • Title states the finding: "Business cards drive the tail of spend", not "Amount by segment".
    • Label units and currency: "AED millions", "per 10,000 transactions".
    • Direct-label lines instead of a distant legend.
    • Colour carries meaning. Few hues, and a palette that survives greyscale and colour-vision deficiency (seaborn's "colorblind" palette works).
    • Show the denominator and uncertainty. A 100% jump in AML alerts from 3 to 6 is a count of three.
    • Arabic text appears as disconnected, reversed letters unless you pass it through a reshaper (arabic-reshaper with python-bidi) and use a font with the glyphs. Test before a board pack.
    • Save vector (SVG or PDF) for documents, PNG at 200 dpi or more for slides, sized in inches so text stays legible.

    Notebooks to reproducible code

    The notebook page and the kernel can disagree. A notebook is a document talking to a running Python process, the kernel. Each cell changes the kernel's memory. Think of a whiteboard where you can rub out a line but the marker pen's earlier effect lingers. You can run cells in any order, edit without rerunning, or delete a cell whose variable still lives in memory. A large study of public notebooks found many could not be rerun to the same result, with out-of-order execution and missing dependencies the main causes (Pimentel et al., 2019).

    Notebooks remain the right place to explore. The discipline is knowing when you have moved to producing something others rely on.

    Each habit closes a specific hole:

    • Restart and run all before you share or believe a number. It clears hidden state and proves the notebook runs top to bottom.
    • Keep cells linear. Imports and settings, then loading, cleaning, analysis. Give new names (df_clean) rather than overwriting df.
    • Set seeds. Anything random (splits, initialisation, sampling, bootstrap) takes a seed: random_state= in sklearn, rng = np.random.default_rng(42) in NumPy. A seed makes a run repeatable, not true; Simulation 4 shows why to also check the spread across seeds.
    • Record the environment. Results depend on library versions. Use one environment per project, a lock file with exact versions (uv, pip-tools or conda lock) and the Python version. An unpinned requirements.txt reproduces nothing six months on.
    • Pin the data. Name the extract, date and query: a snapshot table and as-of date in a config cell, not "the latest data". Point-in-time correctness (F3.1) is part of reproducibility.
    • Put paths and parameters at the top: input table, threshold, date range, seed.
    • Keep outputs out of version control. Notebook files store outputs, including customer data. Strip them before committing (nbstripout). This is a data-handling rule, not a style tip.
    • Move code out when it earns it. A function used in two notebooks, with tests, or feeding production goes into a .py module (F10.3). The notebook becomes the thin story: load, call, plot, comment.
    # src/fraud/features.py  (plain module, importable, testable)
import pandas as pd

def add_velocity(tx: pd.DataFrame, window: str = "1h") -> pd.DataFrame:
    """Count of the customer's transactions in the trailing window."""
    tx = tx.sort_values("ts")
    tx["n_recent"] = (tx.set_index("ts").groupby("customer_id")["amount_aed"]
                        .rolling(window).count().to_numpy())
    return tx

# notebook cell: thin, readable, reruns cleanly
# from fraud.features import add_velocity
# tx = add_velocity(load_snapshot("2026-03-31"))

    Notebook for looking, module for doing. If someone else will run it, it runs on a schedule, or a regulator may ask how a number was produced, make it a script or pipeline with a seed, lock file, tests and recorded data version. If you only needed to find out, a notebook is fine; say so when you share it.

    Seeds repeat a run only on the same library versions and hardware settings (some GPU operations need deterministic modes). "Same seed, different answer" after an upgrade is normal, which is another reason for lock files.

    Part 3

    How it fails, and how to spot it

    These appear in human and AI-generated analyses alike. Each has a quick check.

    • Truncated bar axis

      A 7% rise drawn as threefold. The most common honest mistake.

      Spot itCheck the first y tick on any bar chart. If it is not zero, the lengths mislead.
    • Dual axes that manufacture correlation

      Two lines on separate y-axes can be scaled to cross or track at will.

      Spot itAsk what happens if one axis is rescaled. Prefer two stacked panels sharing the x-axis.
    • Averages drawn as if they were the data

      Mean ticket size per branch hides differences in shape, outliers and sample size.

      Spot itAsk for the distribution (box, violin, ECDF) and the count per group.
    • A binning choice that makes the story

      One hump or two, depending on bin count.

      Spot itRedraw with half and double the bins. If the conclusion changes, say so and show an ECDF.
    • Overplotting and hidden density

      Thousands of points in one blob; dense looks the same as sparse.

      Spot itLower opacity, use hexbin or a 2D histogram, or sample and say so.
    • Unlabelled units, currencies and denominators

      "Losses up 12%" with no base, period or currency.

      Spot itEvery axis and headline number should answer: of what, in what unit, over what period.
    • The notebook that only works in one order

      A cell uses a variable defined further down, or since deleted.

      Spot itRestart and run all. Any error or changed number is the finding. Execution counters not running 1, 2, 3 in order mean suspect state.
    • Seeds as a cure-all, or a cherry-pick

      Fixing random_state=42 and calling it stable, or trying seeds until one looks good.

      Spot itRerun across several seeds and report the spread. One repeatable number from a small test set is a point from a wide distribution.
    • Unpinned environments and "latest" data

      It ran in March; by September a library update or refreshed table changes the answer.

      Spot itLook for a lock file, Python version and dated data snapshot. If any is missing, the result cannot be recreated.
    • Personal data in committed outputs

      A table preview with customer IDs saved in the notebook and pushed to a shared repository.

      Spot itSearch the raw notebook file for output cells. Strip them automatically before commit.
    • Trusting an AI-generated chart because it looks professional

      The code plotted the wrong column, filtered out a segment, or used the default axis.

      Spot itCheck three plotted numbers against a direct computation from the DataFrame. Read the axis limits and filter lines.
    Part 4

    Self-check

    Try each before opening the answer.

    1. A bar chart's y-axis runs from 90 to 100. One bar is 98 and another is 96. How much taller does the first look, and how much larger is it really?

    Heights from the axis start are 8 and 6, so it looks 8 ÷ 6 = 1.33 times as tall (33% more). The values differ by 98 ÷ 96 = 1.02, about 2%. Lie factor is about 16 (33 ÷ 2).

    2. What is the difference between a Figure and an Axes in matplotlib, and why prefer fig, ax = plt.subplots() to bare plt.plot() for kept work?

    The Figure is the canvas; an Axes is one plot area with its own scales and labels. Explicit objects show which plot each call affects, work with several panels and seaborn's ax=, and avoid hidden "current" state.

    3. You see a histogram of loan amounts with one smooth hump. How could it be hiding two customer types?

    Too few bins can smooth two peaks into one. Redraw with more bins, use a log scale for money, or compare an ECDF. Peaks that persist across several bin widths are likely real; ones that appear at a single width are noise.

    4. A notebook's cells show execution numbers 3, 1, 5, 2. What does that tell you, and what do you do?

    The cells ran out of order, so outputs may come from states a top-to-bottom run would not produce. Restart and run all. Fix anything that errors or changes before sharing.

    5. Your recall estimate changes from 76% to 85% when you change the seed of the split. Is the model unstable?

    Probably not; the test set is likely small. With 60 frauds in the test split, the standard error of an 80% recall is √(0.8 × 0.2 ÷ 60) ≈ 5 points, so this range is expected. Report an interval or the spread over many splits, and gather more positives if you need a tighter answer.

    6. List four things that must be recorded so a colleague can reproduce a result in six months.

    Code version, library and Python versions (a lock file), random seeds, and the data snapshot with its as-of date. Also useful: parameters and the command that runs everything.

    7. When should code leave the notebook?

    When it is reused across notebooks, needs tests, feeds production or a scheduled job, or is hard to read in cells. Put it in a module, import it, and keep the notebook as the narrative.

    8. Why might Arabic axis labels look broken in a matplotlib chart, and what is the fix?

    Matplotlib does not do right-to-left shaping or reordering by default, so letters appear disconnected and reversed. Reshape and reorder with arabic-reshaper and python-bidi, use a font with Arabic glyphs, and check the chart visually before circulating.
