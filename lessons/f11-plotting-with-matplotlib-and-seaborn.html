    From DataFrame to Honest Chart, and From Notebook to Code You Can Rerun

    Contents
    Part 1

    The intuition

    A default is a decision someone else made, and you own the chart. Monthly card-fraud losses run AED 41.2m to 44.0m. Start the y-axis at 40 and the room hears "losses tripled"; the real rise is 6.8%.

    A notebook can show a number no clean run would produce. Edit a threshold, delete a cell, and a week later the rerun disagrees with your slide. Both problems share a root: the reader cannot see the process behind the output.

    Hold onto thisAsk of every chart: what is the one conclusion, and could someone reach a wrong one? Ask of every notebook: if I restart and run all, do I get the same numbers?
    Part 2

    How it really works

    Plotting with matplotlib and seaborn

    Matplotlib is the engine; seaborn is the driver. Seaborn takes a DataFrame and column names, does the grouping and calls matplotlib, so you can still adjust the result. For anything you keep, create the Figure (the canvas) and Axes (one plot area) explicitly instead of bare plt.plot(), which relies on a hidden "current" figure.

    fig, ax = plt.subplots(figsize=(7, 4))
sns.histplot(data=tx, x="amount_aed", hue="segment", log_scale=True, ax=ax)

    Let the question pick the chart, using tidy data (one row per observation):

    You want to showReach for
    One distributionHistogram, or ECDF
    Groups comparedBoxplots, overlaid ECDFs
    Change over timeLine chart
    Two numbersScatter; hexbin when dense

    Why the zero rule exists. A bar encodes value as length from a baseline, so a cut baseline is a ruler with its first 40 cm missing. A dot or line encodes position, so a labelled non-zero axis is fine.

    Two more traps. Bin width can create or hide structure (Simulation 2), and overplotting turns 200,000 points into a blob.

    Two habits keep charts honest. State the finding in the title ("Business cards drive the tail of spend"). Label units, currency and denominator: a 100% jump in AML alerts from 3 to 6 is a count of three. Arabic text needs arabic-reshaper, python-bidi and a suitable font, or it shows reversed.

    Notebooks to reproducible code

    The notebook page and the kernel can disagree. A notebook talks to a running Python process, the kernel, whose memory changes with every cell you run, in any order. Notebooks are right for exploring; the discipline is knowing when others begin relying on yours.

    • Restart and run all before you share or believe a number.
    • Set seeds (random_state=, np.random.default_rng(42)). A seed makes a run repeatable, not true (Simulation 4).
    • Pin the environment and the data: a lock file and a dated snapshot, not "the latest".
    • Strip outputs before committing (nbstripout); they can hold customer data.

    Notebook for looking, module for doing. Once code is reused, scheduled or open to audit, move it into a .py module and keep the notebook as the thin story.

    Part 3

    How it fails, and how to spot it

    • Axes that exaggerate

      A truncated bar axis draws a 7% rise as threefold. Dual y-axes can be scaled to say anything.

      Spot itCheck the first y tick on any bar chart. If it is not zero, the lengths mislead.
    • Summaries that hide the data

      Means, bin counts and overplotted points hide shape, outliers and sample size.

      Spot itAsk for the distribution and count per group. Redraw with half and double the bins.
    • Missing units and denominators

      "Losses up 12%" with no base, period or currency.

      Spot itAsk: of what, in what unit, over what period?
    • The notebook that only works once

      Out-of-order cells, deleted variables or a refreshed table change March's answer by September.

      Spot itRestart and run all. Look for a lock file and a dated data snapshot.
    • Seeds as a cure-all, or a cherry-pick

      Fixing random_state=42 and calling it stable, or trying seeds until one looks good.

      Spot itRerun across several seeds and report the spread.
    Part 4

    Self-check

    Try each before opening the answer.

    1. A bar chart's y-axis runs from 90 to 100. One bar is 98 and another is 96. Is the picture honest?

    No. One bar looks about a third taller, but the values differ by about 2%. Start bars at zero, or use dots or a line.

    2. A histogram of loan amounts shows one smooth hump. How could it hide two customer types?

    Too few bins can smooth two peaks into one. Try more bins, a log scale or an ECDF. Peaks that persist across bin widths are likely real.

    3. A notebook's cells show execution numbers 3, 1, 5, 2. What does that tell you?

    The cells ran out of order, so outputs may come from states a top-to-bottom run would not produce. Restart and run all before sharing.

    4. Your recall changes from 76% to 85% when you change the split seed. Is the model unstable?

    Probably not; the test set is likely small. Report the spread over many splits, and gather more positives if you need a tighter answer.

    5. When should code leave the notebook?

    When it is reused, needs tests or feeds production. Put it in a module and keep the notebook as the narrative.
