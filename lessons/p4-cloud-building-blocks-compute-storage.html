    Cloud Building Blocks and GPUs

    Part 1

    What the cloud is

    In one sentenceThe cloud is rented computers, storage and networking, with a permission system on top. You pay for what you use instead of buying hardware.

    A fraud team retrains a model once a quarter. Buying servers for that peak leaves them idle for the rest of the year. Renting means you pay only while you use them, but a forgotten machine keeps billing.

    Every cloud, whatever its brand, is the same four things under different names.

    How it differs from owning

    • Owning: big upfront cost, fixed capacity, you run everything.
    • Renting: pay as you go, capacity on demand, dearer per hour.
    Part 2

    Compute and how you pay for it

    Compute comes in four sizes. Going down the table you control less and do less work.

    KindWhat you rentTypical useWatch for
    Virtual machineA slice of a server with its own operating systemLong training jobs, custom setupsYou patch it; you pay while it is on
    ContainerA packaged program that starts in secondsModel-serving endpoints, scheduled pipelinesRunning a cluster is a skill; use a managed one
    Serverless functionCode run per request, billed by the millisecondLight glue workSlow first start, time limits, rarely GPUs
    Managed ML platformA service that trains or hosts the modelNotebooks, hosted endpointsConvenient but costly; lock-in

    Three ways to pay

    1. On-demand. List price per hour used. Flexible, but the dearest per hour.
    2. Committed. Promise steady spend for one or three years for roughly a third to over half off. You pay whether you use it or not.
    3. Interruptible (spot). Spare capacity at a steep discount, which the provider can take back at short notice. Only for work that can stop and resume.

    How to read it

    A commitment wins only if you use the machine enough. Say it costs 60% of a full month on-demand. Then it is cheaper once you need the machine more than 60% of the hours.

    Always-on scoring endpoint (100% of hours)
    Commit. You pay 60% instead of 100%.
    Nightly job, 3 hours a day (about 12%)
    Stay on-demand. A commitment would pay for the other 88% idle. If the job can restart, interruptible is cheaper still.

    Most surprise bills are something left on, such as a GPU notebook over a weekend. Two habits catch it: autoscaling (machines shut down when idle) and tagging (every resource labelled with its team and project).

    Part 3

    Storage, networking and identity

    Storage: three kinds

    • Object storage: a huge, cheap filing system where each file is fetched whole by name. The default home for ML data and model files.
    • Block storage: a disk attached to one machine, for databases. A shared network drive is file storage.

    Data is encrypted by default. The bank question is who holds the key: with customer-managed keys, disabling the key cuts off access.

    Networking: regions and zones

    • Region: a cluster of data centres in one area. Residency rules are about regions, so banks choose by region.
    • Zone: a separate building inside a region. Two zones survive one building failing. But all zones share the region's network and your own bad deployments, so extra zones help only up to a ceiling. The next step is a second region.

    Identity: who may do what

    Every action is made by an identity, which is a person or a program. A policy says what that identity may do. Think of a hotel key card that opens your room and the gym, not every door.

    • Least privilege: a training job reads one bucket and writes one folder, not "all storage".
    • Short-lived credentials: a token that expires in an hour, not a password in a config file.
    Part 4

    GPUs

    In one sentenceA GPU is a chip with thousands of simple workers doing the same step at once, which suits neural networks, because they are mostly huge piles of identical multiplications.

    A CPU is one chef cooking a complicated dish quickly. A GPU is a thousand people each chopping one onion. Tabular models such as credit scoring run far more cheaply on CPUs.

    Three numbers describe a GPU

    • Memory size (for example 80 GB). The model's weights plus working space must fit.
    • Memory bandwidth (TB/s). How fast weights stream from memory to the workers.
    • Compute (TFLOPS). Raw arithmetic speed.

    Will it fit?

    Weights take parameters × bytes per number. A 70-billion-parameter model is 140 GB at 16 bits, 70 GB at 8 bits and 35 GB at 4 bits. Serving also needs a cache per conversation, and training needs several times more memory than the weights.

    The surprise: generating text waits on memory

    To write one word the GPU reads all the weights once, then does little arithmetic with them. It is a chef with a huge stove waiting for a slow delivery van. The job is memory-bound: speed depends on bandwidth, not on the headline TFLOPS.

    How to read it

    • Speed ceiling for one user = memory bandwidth ÷ weight bytes. A GPU with 3.35 TB/s on a 140 GB model gives at most about 24 words a second.
    • A vendor claims 500 a second on that setup? Doubt it. The model must be smaller, compressed or shared across users.
    • Fewer bits is faster: at 4 bits there are a quarter of the bytes to read.

    Which to use

    Steady, always-on serviceCommitted capacity, in a container
    Restartable trainingInterruptible capacity
    Large language modelGPU with enough memory and bandwidth
    • Strong at: elastic capacity, no hardware to run, pay for use.
    • Weak at: idle machines still bill, data leaving the region costs money, and a bad identity setup exposes data.
    Show the formulas

    Commitment break-even = commit price ÷ on-demand price for the month. At 60%, commit if you need the machine more than 60% of the hours.

    Speed ceiling (words per second, one user) = bandwidth ÷ bytes of weights. The weights are parameters × bytes per number.

    Part 6

    Common mistakes and quick check

    • Paying for idle machines

      A GPU notebook left on all weekend, or a one-year commitment for a 3-hour nightly job. Check utilisation per resource, and set auto-shutdown and budget alerts.

    • Over-broad identity

      A shared admin key or credentials in code. Ask which identity each job runs as and what it can touch.

    • Public by accident

      A bucket or endpoint reachable from the internet. Private network paths and policy checks should make this impossible, not just unlikely.

    • Counting TFLOPS for a memory-bound job

      Buying the biggest headline number for single-user text generation. Divide bandwidth by model bytes first.

    1. A commitment costs 60% of on-demand. A job needs a machine 4 hours a day. Which is cheaper?

    On-demand. The job uses about 17% of the month, far below 60%.

    2. Why does a third zone help little?

    Shared parts of the region (network, control plane, your own deployments) fail across all zones together and set a ceiling. The next step is a second region.

    3. How much memory do the weights of a 70B model need at 8 bits?

    About 70 GB (70 billion × 1 byte), plus room for the cache.

    4. Why is generating text memory-bound?

    Each word needs all the weights read once with little arithmetic, so memory bandwidth, not compute, sets the speed.
